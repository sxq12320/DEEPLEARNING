# 柑橘套袋视觉研究总纲与第一篇论文执行方案

> 版本：2026-07-13
> 目标：以硕士毕业为第一优先级，尽快完成第一篇可投稿论文，并保证两篇小论文能够组成逻辑完整的毕业论文。
> 当前范围：RGB 图像、柑橘幼果、实例分割。本文是本课题唯一研究计划，旧调研文档已合并删除。

## 1. 开宗明义

课题不是完整套袋机器人系统，而是面向柑橘套袋作业的两阶段视觉感知研究。

| 阶段 | 论文任务 | 输入 | 输出 | 作用 |
|---|---|---|---|---|
| 第一篇 | 柑橘幼果实例分割 | 果园 RGB 图像 | 每个幼果的检测框与实例掩膜 | 找到果实并获得精确 ROI |
| 第二篇 | 柑橘果梗点精准定位 | 原图 + 第一篇的果实 ROI/掩膜 | 果梗连接点、可见性与置信度 | 给出套袋扎口和逼近参考点 |

```mermaid
flowchart LR
    A[果园 RGB 图像] --> B[论文一：幼果实例分割]
    B --> C[果实实例、轮廓和 ROI]
    C --> D[论文二：掩膜引导的果梗点定位]
    D --> E[果梗点、可见性和定位置信度]
    E --> F[面向套袋作业的视觉感知链]
```

第一篇不加入 OBB、机械臂控制、RGB-D、amodal 补全或多任务果梗头。这些内容会延长开发周期并削弱“幼果实例分割”这一核心问题。第二篇直接复用第一篇的实例结果，形成自然衔接。

## 2. 当前资产与已验证事实

### 2.1 数据集

当前数据位于 `E:/mastercode/data/test/`，共 941 张图像、4,576 个幼果实例，现有划分为 659/188/94。数据包含两个明显不同的采集批次：

| 批次 | 图像数 | 主要特征 |
|---|---:|---|
| 2023 批次 | 116 | 果实较亮、部分有高光、密集簇生和连拍图较多 |
| 2026 批次 | 825 | 深绿色哑光幼果，与叶片颜色接近 |

标签统计给出了三个可直接写入论文动机的事实：

- 每图平均约 4.8-5.2 个实例，单图最多 35 个实例。
- 在 640 输入下，约 34.9%-40.5% 的实例至少一边小于 32 像素，约 11.3%-12.8% 小于 16 像素。
- 约 47.0%-58.5% 的图像存在相邻或接近粘连的实例，38.7%-46.8% 的图像存在实例外接框重叠。

“果实与叶片同色”目前有真实图像证据，但还缺少量化。正式论文需要计算果实区域与局部背景环带的 CIELAB 色差、直方图距离和梯度/纹理差异，不能只依赖主观描述。

### 2.2 数据泄漏风险

当前划分把同一连拍序列分到了不同集合。例如 `IMG20231120161107_BURST*` 同时出现在 train、val、test。近重复图像会抬高验证和测试指标，因此当前 001-003 结果只能作为预实验。

正式数据协议必须包含：

1. 按连拍序列、采集时间或同一果簇分组，组内图像不得跨集合。
2. 主表使用分组后的混合域 train/val/test。
3. 增加跨批次测试：以 2026 批次训练和验证，以 2023 批次作为独立外部测试。
4. 测试集在方法定稿前不得反复查看或调参。

### 2.3 已完成预实验

| 模型 | Params | GFLOPs | 推理时间 | Mask mAP50-95 | 结论 |
|---|---:|---:|---:|---:|---|
| 001 YOLO11n-Seg | 2.835M | 10.2 | 6.6 ms | **0.642** | 当前精度基线 |
| 002 StarNet-YOLO11n-Seg | **2.261M** | **8.4** | **5.6 ms** | 0.612 | 真正变轻，但损失约 3.0 个点 |
| 003 MobileNetV4-YOLO11n-Seg | 3.675M | 11.7 | 12.3 ms | 0.606 | 更重、更慢且精度下降，停止投入 |

## 3. Baseline 选择与非 YOLO 对比

### 3.1 主 baseline

现阶段主消融 baseline 仍选择 **YOLO11n-Seg**，理由如下：

1. 模型本身是 nano 级，符合轻量化目标。
2. 本地已有完整训练结果、误差曲线和可视化。
3. 近期橙果实例分割和轻量农业分割研究大量采用 YOLO11n-Seg，便于正面对比。
4. 当前 fork、训练脚本和自定义模块均围绕 YOLO11 架构，能最快形成可复现实验。

这只是快速开发选择，不代表论文对比可以局限在 YOLO。为降低“又一篇改进 YOLO”带来的同质化风险，必须并行筛选 **RTMDet-Ins-tiny**。它是成熟的非 YOLO 一阶段实例分割器，官方 640 输入配置约 5.6M 参数、11.8 GFLOPs，规模与 YOLO11n-Seg 接近，适合作为最重要的轻量公平对照。

在修复数据划分后，先让 YOLO11n-Seg 与 RTMDet-Ins-tiny 各训练 50 epoch：

- 若 RTMDet 的 Mask mAP50-95 与 YOLO11n 相差不超过 1.5 点、训练稳定且难例表现更好，可讨论将其切换为主 baseline；
- 若框架适配明显拖慢进度，或精度落后超过 1.5-2.0 点，则维持 YOLO11n 为主消融 baseline，RTMDet 作为必做的非 YOLO 横向对照；
- 在短筛选结果出来前，不同时为两个框架开发本文模块。

StarNet 是“全量替换 backbone 过度压缩导致精度下降”的轻量化对照。MobileNetV4 仅保留为负结果或附录，不再作为主线。

### 3.2 核心与增强对比模型

| 角色 | 模型 | 目的 |
|---|---|---|
| 旧代轻量模型 | YOLOv8n-Seg | 证明提升不是只来自代际更新 |
| 主消融基线 | YOLO11n-Seg | 与每个改进逐项比较 |
| 当前 YOLO 强对照 | YOLO26n-Seg | 回答“为什么不比较最新 YOLO” |
| **非 YOLO 轻量对照** | **RTMDet-Ins-tiny** | 同为 640 输入的一阶段实时实例分割，必做 |
| **经典两阶段** | **Mask R-CNN R50-FPN** | 建立 proposal-based 标准基线，必做 |
| **当前 Transformer** | **RF-DETR Seg Nano** | 代表 2026 年端到端实例分割路线，强烈建议 |
| **无框位置实例分割** | **SOLOv2-Light R18-FPN** | 检验按位置生成动态 mask 对深凹轮廓、密集邻果和跨尺度实例的适应性，期刊版建议 |
| **经典语义分割** | **U-Net + marker watershed** | 检验语义前景分割经传统分离后能否处理粘连，必做辅助基线 |
| 语义分割补充，可选 | DeepLabV3+ 或 SegFormer-B0 + watershed | 二选一补充多尺度 CNN 或轻量 Transformer 语义路线 |
| 动态/稀疏实例，可选替代 | CondInst R50-FPN 或 SparseInst | 仅在不做 SOLOv2 时二选一，不与 SOLOv2 同时堆叠 |
| 同家族精度上界，可选 | YOLO11s-Seg | 判断 nano 与更大 YOLO 的差距 |

YOLO26n-Seg 在当前 fork 中可正常构建，约 3.126M 参数、11.14 GFLOPs；它比 YOLO11n-Seg 略重，因此适合作为强对照，而不是本课题的轻量主基线。

核心实例分割表的最小可投稿对比集为 6 个模型：YOLOv8n-Seg、YOLO11n-Seg、YOLO26n-Seg、RTMDet-Ins-tiny、Mask R-CNN R50-FPN 和 RF-DETR Seg Nano。期刊增强版加入 SOLOv2-Light R18-FPN，形成 7 个模型的跨范式比较；加入后不再同时增加 CondInst 或 SparseInst。另设语义分割辅助表，至少加入 U-Net + watershed；DeepLabV3+ 与 SegFormer-B0 二选一。这样覆盖旧代/当前 YOLO、非 YOLO 一阶段、经典两阶段、当前 Transformer、无框位置分割和语义转实例路线，不需要为了数量堆满所有老模型。

SOLOv2 使用 MMDetection 的 `solov2-light_r18_fpn_ms-3x_coco.py` 与 COCO 预训练权重。它通过位置条件动态 mask kernel 和 Matrix NMS 直接生成实例，适合作为本课题“遮挡深凹轮廓 + 密集邻果分离 + 图内极端尺度跨度”的诊断对照。但其位置网格与当前 Ultralytics 改进路径差异较大，因此只做横向比较，不把本文模块移植到 SOLOv2 上，也不将其改为主消融 baseline。

以下模型不适合作为主要公平 baseline：

- SAM/MobileSAM：需要点、框或文本提示，不是同一自动实例检测任务；
- 不带后处理的纯 U-Net/DeepLab：只输出语义 mask，不能直接区分相邻实例；
- Mask2Former：可作为高精度上界，但计算与显存成本较高，快速投稿阶段优先级低；
- 仅检测模型：没有实例 mask，不能放入同一核心表。

### 3.3 跨框架公平训练协议

Ultralytics 模型先用短实验确定协议，随后冻结全部非结构变量。建议正式配置为：

```yaml
epochs: 300
imgsz: 640
batch: 4
optimizer: AdamW
lr0: 0.001
dropout: 0.0
patience: 100
seed: 42
deterministic: true
amp: false
```

Stock YOLO 模型使用对应的官方 COCO 预训练权重。改进模型从 `yolo11n-seg.pt` 迁移所有形状匹配层，并报告成功迁移的层数或参数比例。筛选实验只跑一个种子；主 baseline 和最终模型使用三个种子，报告均值和标准差。

跨框架对比不能简单强迫所有模型使用 AdamW 和同一学习率。公平原则是：

1. 使用完全相同的 group-aware train/val/test 图像清单和类别定义；
2. 主精度表尽量统一为 640x640，RF-DETR 使用其支持的相同或最近分辨率；
3. 所有模型使用官方 COCO 预训练，并采用各自稳定的官方优化器和学习率比例；
4. 固定训练图像总次数、数据增强边界和验证频率，记录实际 wall-clock 时间；
5. Params、GFLOPs、显存和 batch=1 延迟在同一硬件、精度模式和输入尺寸下重新测量；
6. 不把 RF-DETR 默认 312 分辨率的官方速度与本项目 640 分辨率结果直接比较；
7. 完整 baseline 表保存每个框架的配置文件、命令、版本和权重来源。

U-Net 类模型采用统一的语义转实例协议：

1. 将所有实例标签合并为幼果二值前景，训练 U-Net；
2. 使用距离变换生成 marker，并采用 marker-controlled watershed 分离接触果实；
3. 所有阈值只在 val 集确定，test 集不单独调参；
4. 语义结果报告 Dice、mIoU、Boundary F1；
5. watershed 连通区域转换成实例后，再报告与其他模型相同的 Mask mAP；
6. 论文表中模型名写为 `U-Net + Watershed`，不能把它简称为 U-Net 实例分割。

正式 U-Net baseline 使用 `segmentation_models_pytorch` 或 MMSegmentation 的成熟实现，并固定 encoder 与 ImageNet 预训练。`1.coding/2_Unet/` 是早期学习代码，当前输出通道固定为 21，数据和评估协议也不适配本课题，不直接用于论文结果。

Baseline 检索与实施审计保存在 `sources/research_instance_segmentation_baselines_2026.md`。

## 4. 第一篇论文真正要解决的视觉难点

### 4.1 先排除不能作为核心创新的常见难点

“幼果与叶片同色、光照变化、遮挡、小目标、密集果簇”在本数据中都真实存在，但相关绿果、柑橘、伪装目标和农业实例分割论文已经大量讨论。它们可以写入应用背景，不能单独支撑“大创新”。尤其需要注意：

- 2024 年已有面向幼桃套袋机器人的轻量 YOLOv8n-Seg 轮廓提取与生长姿态估计；
- 2026 年已有橙果 YOLO11n-Seg 工作直接处理果实粘连、叶片遮挡和模糊，并采用边界引导与轻量卷积；
- 伪装实例分割、频域感知、小波高频增强和 amodal 果实补全都已有先例。

因此，第一篇要从“严重遮挡”继续下钻到遮挡的具体形态、mask 误差类型和可量化属性。

### 4.2 第一核心难点：条带遮挡切割出的深凹轮廓

柑橘叶片和细枝经常以狭长条带横穿果面，不是简单遮住果实的一整侧。这会把近圆形幼果的可见 mask 切出深凹缺口、狭窄残留区，严重时同一果实只剩多个局部可见区域。算法面临两个相反要求：

1. 必须沿叶缘准确停止，不能把遮挡叶片填成果实；
2. 又要维持同一果实的实例身份，不能把剩余可见区域错判成多个果实。

用多边形面积除以凸包面积的 `solidity` 作为初步代理，在 4,576 个实例中：

- 约 24.0% 的实例 `solidity < 0.90`；
- 约 7.5% 的实例 `solidity < 0.80`。

这说明相当一部分标签具有明显非凸轮廓，但不能直接等同于遮挡率。正式论文必须人工复核低 solidity 样本，排除图像边界截断、天然形变和标注误差，再建立 `concave-occlusion` 子集。

### 4.3 第二核心难点：遮挡与接触造成相反的拓扑错误

密集果簇中，相邻幼果颜色、纹理和曲率相近，分界有时只剩一条窄阴影。当前统计显示约 47.0%-58.5% 的图像存在相邻或近粘连实例，38.7%-46.8% 的图像存在实例外接框重叠。

遮挡与粘连对模型提出相反要求：

- 叶片切入一个果实时，模型需要保持“这仍是同一个实例”；
- 两个果实接触时，模型必须保持“这是两个不同实例”。

这可定义为**遮挡-接触拓扑冲突**。典型错误包括同果错分、两果合并、接触走廊桥接和跨实例泄漏。普通前景 Dice 或总体 Mask IoU 对细小桥接不够敏感，U-Net 等语义模型尤其容易把接触果簇输出为一整块前景。

### 4.4 第三核心难点：同色果-叶的纹理混叠

困难不只是幼果和叶片颜色接近。果皮油胞形成颗粒高频纹理，叶脉、灰尘、病斑和反光也会产生强高频响应，因此“增强高频”可能同时增强目标与背景干扰。

当前可提出但尚未证实的视觉假设是：

- 果皮纹理更接近各向同性颗粒与缓慢球面明暗；
- 叶片纹理更偏方向性叶脉、长边缘和局部平面反光；
- 这种差异在 2023 高光批次和 2026 深绿哑光批次间可能发生变化。

正式采用纹理模块前，必须计算果实与局部背景的 CIELAB 色差、梯度能量、LBP/频谱和结构张量方向一致性。若统计不能稳定区分果实与叶片，就删除“纹理各向异性”创新，不要先设计模块再寻找解释。

### 4.5 第四核心难点：单图极端尺度跨度

该数据不是只有“小目标多”，而是同一张图同时出现近景大果和远景微小果。对至少包含两个实例的 744 张图像：

- 单图最大/最小实例面积比中位数约为 6.0；
- 33.6% 的图像面积比超过 10；
- 13.2% 超过 25；
- 最大约为 228。

这会使同图实例跨越多个特征层级，并使固定分辨率 prototype mask 对远景小果边界造成更大损失。单纯增加 P2 检测头是常见做法，不能作为主要创新，但该尺度属性应成为模型筛选和专项评价条件。

### 4.6 辅助难点：边界截断与跨批次外观变化

约 10.1% 的实例接触图像边界，27.6% 的图像至少包含一个截断实例。2023 与 2026 批次还存在颜色、光泽、拍摄距离和密度变化。这两项适合建立 `truncated` 与 `cross-batch` 子集，更接近数据协议和泛化问题，不单独作为核心算法创新。

### 4.7 难点优先级结论

| 候选难点 | 具体性 | 文献拥挤程度 | 当前可量化性 | 定位 |
|---|---:|---:|---:|---|
| 同色、普通遮挡、小目标 | 低 | 高 | 中 | 只作背景 |
| 条带遮挡与深凹轮廓 | 高 | 中 | 高 | 第一核心难点 |
| 同类果实粘连 | 中 | 中高 | 高 | 不能单独主张 |
| **遮挡-接触拓扑冲突** | **高** | **中低** | **高** | **最推荐创新交集** |
| 果-叶纹理混叠 | 高 | 中 | 待验证 | 条件性创新 |
| 单图极端尺度跨度 | 高 | 高 | 高 | 重要辅助难点 |
| 方向性入袋边界 | 作业约束 | 低 | 需机构定义 | 附加评价，不作视觉主线 |

第一篇的科学问题建议写成：

> 在同色冠层和单图极端尺度跨度下，轻量实例分割网络如何处理条带遮挡造成的深凹轮廓，并同时保持被遮挡果实的实例身份和相邻接触果实的实例分离？

当前较少被直接研究的不是“柑橘难分”，而是：

1. **条带遮挡形成的深凹可见轮廓是否被单独建模和评价；**
2. **同一果实在遮挡下需要保持身份、不同果实在接触下需要分离的拓扑冲突是否统一处理；**
3. **轻量化压缩是否保护低 solidity、小尺度和相邻接触实例，而不是只追求总体 mAP。**

可争取的创新交集是：

> 面向条带遮挡与同类接触共存的幼果场景，建立凹陷遮挡边界和相邻实例分离监督，在保留浅层轮廓能力的同时压缩深层网络，并在总体精度之外报告低 solidity 边界质量、间隙保持和 split/merge 错误。

“首个”或“首次”只能在完成全文检索后使用。现阶段采用“面向”“针对”或“据检索尚缺少系统研究”等保守表述。完整检索审计保存在 `sources/research_citrus_bagging_unique_visual_difficulties.md`。

## 6. 推荐方法：CitrusTopo-Seg

推荐中文题目：

> **面向遮挡-接触拓扑冲突的轻量化柑橘幼果实例分割方法**

暂定英文题目：

> **CitrusTopo-Seg: Lightweight Topology-Aware Instance Segmentation for Occluded and Adherent Immature Citrus**

方法暂以 YOLO11n-Seg 为开发基线，同时用 RTMDet-Ins-tiny 做非 YOLO 筛选。主线是：深层压缩降低成本，保留浅层特征避免凹陷轮廓过早消失，再用拓扑相关监督分别处理“同果被遮挡”和“异果相接触”。

### 6.1 创新一：边界保真的分阶段轻量化

现有 StarNet 全 backbone 替换将参数量从 2.835M 降到 2.261M、GFLOPs 从 10.2 降到 8.4，但 Mask mAP50-95 下降约 3.0 个点。这说明“压缩有效、轮廓能力受损”，可以转化为方法动机。

设计 **Boundary-Preserving Stage-wise Compression（BPSC）**：

1. 保留浅层 P2/P3 的原始细节提取结构，避免同色弱边缘在早期下采样中消失；
2. 只在语义更强的 P4/P5 或 neck 深层位置使用 StarBlock/深度可分离结构；
3. 逐层比较替换位置，选择真实 GPU 延迟和精度最优的配置；
4. 不引入 FFT、小波双分支或大型注意力，降低与现有频域和边界增强论文的同质化；
5. 目标为 Params、GFLOPs 至少降低 10%，实测延迟不劣于 YOLO11n-Seg。

BPSC 的贡献不是发明新的基础卷积，而是**按套袋关键轮廓的层级需求进行非均匀压缩**。如果实验表明深层替换仍明显损害边界，则轻量化应改用通道宽度搜索或训练后剪枝，不强行保留 StarBlock。

### 6.2 创新二：凹陷遮挡边界损失

设计训练期使用的 **Concave Occlusion Boundary Loss（COB Loss）**。对每个非截断真实实例：

1. 计算实例 mask、凸包与凸包缺口区域；
2. 找出与凸包缺口相邻的深凹边界，作为条带遮挡候选区域；
3. 在该区域计算预测边界与真实可见边界的距离、漏分和外溢；
4. 按凹陷深度、实例尺度和局部颜色对比度分配权重；
5. 与原 mask loss 相加，只增加训练成本，不增加推理参数。

COB Loss 学习的是当前 modal 标签中的可见凹陷边界，不做 amodal 补全。低 solidity 只用于候选筛选，正式训练前必须排除图像截断和明显错误标签，避免把标注噪声放大。

### 6.3 创新三：相邻实例排他损失与评价

设计 **Adjacent Instance Exclusivity Loss（AIE Loss）**。从标签中自动寻找距离小于阈值的相邻实例对，在两实例的接触走廊中：

- 惩罚预测 mask 进入邻果真实区域的 cross-instance leakage；
- 惩罚两个预测 mask 在狭窄间隙处形成桥接；
- 保留真实间隙，不要求人为扩大果间距离；
- 只对近邻实例对计算，避免全图两两比较。

除标准 mAP 外，新增三个可解释指标：

1. `Concave-BF1`：仅在凹陷遮挡边界上计算的边界 F1；
2. `Gap-Preservation`：真实相邻间隙被正确保留的实例对比例；
3. `Split/Merge Error`：相邻果实发生错分、合并或跨实例泄漏的比例。

不要急于把三个指标加权成自定义总分。分开报告更透明，也更容易被审稿人接受。

### 6.4 难例分层基准

利用现有标签自动构造并固定以下子集：

1. `small`：按 640 尺度下的实例尺寸划分；
2. `dense`：按每图实例数划分；
3. `adjacent-pair`：按实例最小边界距离划分；
4. `concave-occlusion`：按 solidity、凸包缺口和人工复核划分；
5. `scale-span`：按单图最大/最小实例面积比划分；
6. `truncated`：图像边界截断实例；
7. `cross-batch`：按采集批次进行外部测试。

`concave-occlusion` 不需要重做全量像素标签。先自动筛选低 solidity 实例，再由两名标注者独立给出无遮挡、叶片遮挡、枝条遮挡、邻果遮挡、边界截断和标注异常属性，并报告一致性。该小规模属性集足以验证 COB Loss 是否真正改善条带遮挡，而不是只拟合不规则多边形。

### 6.5 备选而非主线

原计划的 CFTB/CABI 和方向性 DBB 不再作为默认核心创新。只有当纹理统计证明果皮与叶片存在稳定的方向性差异时，才增加一个轻量纹理判别分支；不能先堆小波、注意力、DCN、GSConv 和新上采样再解释。amodal 包络、障碍物分割和机器人可达性明确留到后续，不进入第一篇快速投稿范围。

### 7.2 BPSC 消融

- 全 backbone 替换、仅 P5 替换、P4+P5 替换；
- backbone 深层替换与 neck 深层替换；
- 不同通道压缩率；
- 是否保留 P2/P3 原结构；
- Params、GFLOPs、显存、GPU 延迟和导出兼容性；
- 总体 Mask AP 与 Concave-BF1 的同步变化。

### 7.3 COB/AIE 消融

- 仅普通 mask loss；
- 普通全边界 loss；
- 仅 COB Loss；
- 仅 AIE Loss；
- COB + AIE；
- solidity/凹陷深度筛选阈值；
- 近邻实例距离阈值；
- 不同权重系数的敏感性。

### 7.4 必报指标

主指标为 Mask mAP50-95。完整报告：

- Mask mAP50-95、Mask mAP50、Box mAP50-95；
- mask precision、recall、F1；
- AP-small、AP-medium、AP-large；
- Concave-BF1、Gap-Preservation、Split/Merge Error；
- small、dense、adjacent-pair、concave-occlusion、scale-span、truncated 子集指标；
- 跨批次测试指标；
- Params、GFLOPs、模型大小、显存、batch=1 延迟和 FPS；
- 三次运行的均值与标准差；
- 典型成功案例和失败案例。

没有 Jetson 或实际边缘设备测试时，只能称“lightweight”或“efficient”，不要声称已经完成边缘部署。

### 7.5 成功判据

“轻量化 + 高精度”必须同时满足：

1. 完整模型的参数量和 GFLOPs 相对 E0 至少下降 10%，或实测延迟有明确下降；
2. group-aware 测试集 Mask mAP50-95 不低于 E0，目标为高于 E0；
3. Concave-BF1 与 Gap-Preservation 均高于 E0，且 Split/Merge Error 下降；
4. small、adjacent-pair、concave-occlusion、scale-span 至少两个子集稳定提升；
5. 三种子结果方向一致。

若总体 mAP 小幅变化但作业关键指标明显改善，论文可以表述为“在降低成本的同时提高套袋关键轮廓完整性”，但必须同时公开总体指标，不能只报告自定义指标。若模型只变轻且关键指标仍下降，则只能称为精度-效率折中。

## 9. 第一篇论文写作骨架

推荐中文题目：

> 面向遮挡-接触拓扑冲突的轻量化柑橘幼果实例分割方法

论文叙事顺序：

1. 套袋视觉需要先获得独立幼果实例和可靠可见轮廓；
2. 条带叶片/枝条把果实切成深凹轮廓，而同色邻果接触又会消除实例间隙；
3. 现有工作分别研究遮挡、粘连和边界，但较少统一处理“同果需保持、异果需分开”的拓扑冲突；
4. 提出 BPSC，保留浅层轮廓能力并压缩深层网络；
5. 提出 COB Loss 与 AIE Loss，分别监督凹陷遮挡边界和相邻实例接触走廊；
6. 在总体、凹陷遮挡、相邻接触、极端尺度、跨批次和效率指标上验证方法。

摘要和结论只能填写真实实验数字。禁止提前写“显著提升”“首次”“达到实时部署”或虚构定位误差。

## 10. 第二篇论文的接口

第二篇不再做普通果梗分割，因为 2025 年已经存在改进 YOLOv8 果梗分割和 RG-YOLO-Seg 果梗精确定位工作。第二篇应定义为：

> **实例掩膜引导、面向遮挡与不可见性的柑橘果梗连接点精准定位。**

建议输入为原图、果实 crop、第一篇 mask 和轮廓；输出为果梗点坐标、visible/occluded 状态和定位不确定性。核心问题应是遮挡果梗的上下文推断、轮廓与果梗连接关系以及归一化定位误差，而不是再次堆叠检测模块。

这样，大论文可以形成完整故事：

> 幼果同色伪装实例分割 -> 单果 ROI 与轮廓 -> 果梗连接点精定位 -> 套袋视觉关键感知信息。

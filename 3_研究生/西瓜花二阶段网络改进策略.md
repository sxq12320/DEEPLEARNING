# 西瓜花二阶段网络改进策略

## 1. 现有方案是否合理

你现在的流程：

1. 用 YOLO 分割西瓜花掩码  
2. 从掩码轮廓取 64 个点并求质心  
3. 用 64 个点回归“质心到 GT 授粉点”的偏差  
4. 计算最终指标  

这个思路**可以成立**，尤其适合作为一个工程上容易跑通的二阶段基线。但它目前更像“可用基线”，还不是最稳的方案。核心问题不是网络能不能学，而是**输入表达、GT 匹配、误差传播和评价方式**都还有提升空间。

## 2. 目前方案的优点

- 分割先把背景去掉，降低了直接在整图上找授粉点的难度。
- 用轮廓点而不是整张图，计算量低，训练速度快。
- 用“质心 + 偏移”来回归，任务定义清晰，容易收敛。

## 3. 目前最主要的问题

### 3.1 分割误差会直接传导到关键点

如果分割掩码偏移、破碎、缺边，后面的 64 点、质心、偏移回归都会一起偏。

### 3.2 64 个轮廓点的信息仍然偏弱

只保留轮廓，丢掉了内部纹理、雄蕊结构、亮度分布这些对授粉点很关键的信息。  
如果授粉点更多由花心内部视觉特征决定，只靠轮廓会有上限。

### 3.3 “质心到 GT 偏移”并不一定稳定

当花朵姿态变化、遮挡、掩码缺损时，质心本身会漂移。  
这会导致你的回归目标不稳定，网络学到的是“分割误差 + 几何误差 + 授粉点误差”的混合量。

### 3.4 GT 匹配规则必须严格统一

一张图里可能有多个点标注，必须按“离当前花朵中心最近的可见点”去匹配，并剔除 `invisible`。  
否则训练和评估会混入错误监督。

### 3.5 指标不能只看像素误差

建议同时报告：

- 平均像素误差
- 中位像素误差
- `mAP50`
- `mAP50-95`

关键点任务最终还是要用基于 OKS 的 mAP 才更完整。

## 4. 优先级最高的改进

## 4.1 先把数据和评估协议固定住

这是第一优先级，收益最大：

- 只使用和当前花朵掩码匹配的可见 GT 点
- 过滤 `invisible`
- 对过远的点设置距离阈值，避免错配
- 统一训练、验证、可视化三套脚本的 GT 选择逻辑
- 统一输出 OKS `mAP50/mAP50-95`

如果这一步不统一，后面的网络改进很难判断是否真的有效。

## 4.2 保留二阶段，但第二阶段不要只吃轮廓点

短期最推荐的做法是：

- 第一阶段仍然用 YOLO 分割
- 用分割框或最小外接矩形裁一个 ROI
- 第二阶段输入改成“ROI 小图 + 掩码”或“ROI 小图 + 轮廓点”
- 让网络直接预测关键点热图或归一化坐标

这样比“只有 64 个边界点”更稳。

## 4.3 如果仍然坚持轮廓点输入，建议补几何特征

建议增加：

- 掩码面积
- 周长
- 长宽比
- 椭圆主轴/次轴
- 圆度
- 凸包面积与凹陷程度
- 质心到轮廓各点的径向距离序列
- 曲率极值点

这比只给 `(x, y)` 轮廓点更有信息量。

## 5. 更推荐的模型方向

### 方向 A：低风险、最值得先试

**YOLO 分割 + ROI 裁剪 + 小型关键点热图网络**

原因：

- 对分割误差更鲁棒
- 能利用花心内部纹理
- 输出热图比直接回归偏移更稳定

这是我最推荐的下一步。

### 方向 B：保持轮廓路线，但增强表示

**轮廓点序列 + 几何统计量 + 可见性约束 + 不确定性回归**

适合你现在的代码基础，改动小，但上限通常不如热图方法。

### 方向 C：长期方向

**直接做端到端关键点检测或多任务学习（分割 + 关键点）**

例如一个模型同时输出花朵掩码和授粉点。  
这样可以减少阶段间误差传导，但训练要求更高。

## 6. 具体落地建议

建议按下面顺序改：

1. 先固定 GT 匹配和 OKS mAP 评估  
2. 把第二阶段从“偏移回归”改成“ROI 热图预测”  
3. 若继续用轮廓点，加入面积、主轴、曲率、径向距离等特征  
4. 做消融实验：`仅轮廓`、`轮廓+HSV`、`ROI图像`、`ROI图像+掩码`  
5. 最终用 `mAP50`、`mAP50-95`、中位误差三项一起选模型

## 7. 结论

你的二阶段思路**不是错**，但当前版本的瓶颈不在“网络还不够深”，而在：

- 输入表达太弱  
- 质心偏移目标不够稳  
- 分割误差直接放大  
- 评估协议之前不统一  

如果只允许我给一个最值得改的方向，我建议：

**保留第一阶段分割，第二阶段改成 ROI 关键点热图网络，而不是只用 64 个轮廓点做偏移回归。**

# G_0839 实现状态与实验判据

## 1. 定位

`G_0839` 是 Citrus SDR-Net 概念的第一套可训练结构消融，不是旧 `G_series/G10` 的延续。当前只完成工程实现和梯度验证，**没有精度结论**。G00 是统一轻量头控制组；G01--G05 使用全新的非 C3k2 双分辨率主干。

## 2. 主干为什么不再使用 C3k2

新 `CitrusDualResolutionBackbone` 把特征提取拆成两条职责不同的路径：

1. stride-4 P2 细节流从主干入口一直保留到出口，负责微小像素、可见边界和凹口；
2. P3--P5 语义流通过低通平均池化降采样和深度可分残差块提取上下文，主干内没有 C3k2/CSP；
3. 三个 stage 都用语义门控 P2 更新，避免叶片纹理无条件进入高分辨率流；
4. P2 经过尺度匹配后回送语义流，使小目标形状不会只停留在浅层；
5. 颈部暂时保持相同 YOLO PAN/C3k2，确保 G00→G01 的主要变量是主干。若 G01 失败，不应立即继续换颈部掩盖失败原因。

结构依据分别来自 Lite-HRNet 的持续高分辨率表示、PIDNet 的 detail/context 分工和受控融合、Gated-SCNN 的语义门控形状流、PiDiNet 的像素差分结构证据。实现根据机制重新编写，没有复制许可证受限仓库代码。

## 3. 消融矩阵

| 模型 | 主干 | 新增阶段 | Params | GFLOPs@640 | 默认辅助损失 |
|---|---|---|---:|---:|---|
| G00 | YOLO11 C3k2 | 轻量头控制 | 2.716M | 9.62 | 无 |
| G01 | 双分辨率非 C3k2 | Preserve | 2.732M | 10.71 | 无 |
| G02 | 同 G01 | Search | 2.741M | 10.95 | query 0.03 |
| G03 | 同 G01 | Discriminate | 2.742M | 10.97 | + contrast 0.05 |
| G04 | 同 G01 | Boundary refine | 2.742M | 11.00 | + boundary 0.10 |
| G05 | 同 G01 | Topology separator | 2.742M | 11.00 | + topology 0.05 |

实现时六个模型统一接收完全相同的 gain 向量：query 0.03、contrast 0.05、boundary 0.10、topology 0.05；模型没有相应输出时该项为零。上表“默认辅助损失”表示各阶段实际激活的输出，不表示命令行超参数不同。基础训练协议统一读取 `CITRUS_FORMAL_PROTOCOL.md` / `protocols/citrus_paper1_formal_v1.yaml`。

G02 的 top-k 在当前 PyTorch 实现中稀疏的是信息支持区域，不是卷积算子执行；因此不能在论文中直接宣称 QueryDet 式实测加速。只有后续实现 ROI gather/scatter 或专用稀疏 kernel 并测得 latency 降低后，才能写计算稀疏性。

## 4. 每一步的保留条件

| 比较 | 必须主要改善的量 | 失败后的动作 |
|---|---|---|
| G01 vs G00 | AP-small、tiny recall、低 solidity recall；总 AP 不应显著下降 | 新主干归档，不用 G02--G05 的结果掩盖主干失败 |
| G02 vs G01 | tiny recall、候选召回；高 recall 端 precision 不恶化 | 删除 Search 或重新调 top-k，不添加 score calibration 粉饰 |
| G03 vs G02 | low-contrast/低 Lab ΔE 子集 FP、precision、PR 尾部 | 删除 context loss/门控，不称解决伪装 |
| G04 vs G03 | Boundary F1、Concave-BF1、AP75 | 删除边界阶段，不能只凭 AP50 保留 |
| G05 vs G04 | near-gap、concave+near 的 merge/split 和 cross-instance leakage | 删除 topology；若 recall 降低，先降低 topology gain 再做一次受控 loss 消融 |

任何阶段都不能仅凭一次 mAP50 上升保留。G04/G05 的价值必须由挑战子集指标证明。

## 5. 已完成验证

- 六个 YAML 可通过官方 `YOLO(yaml, task="segment")` 构建和推理；
- G05 可加载 YOLO11n-seg 权重，因主干整体更换而只迁移兼容的颈部/头部张量：253/614 项；
- G05 的标准实例分割损失和 query、contrast、boundary、topology 均完成反向传播；
- 梯度到达新主干双向交换、查询、上下文、边界、拓扑和原型残差；
- G/C/D 相关回归测试共 43 项通过；
- 完整模型 2.742M 参数、11.00 GFLOPs，满足 nano 级工程门槛。

这只能证明“代码可训练且规模合格”，不能证明“方法有效”。

## 6. 下一步

先在服务器依次执行 3 epoch smoke 和 50 epoch G00--G05 screening。筛选后只让 1--2 个模型进入 300 epoch；最终方法和同协议官方 YOLO11n-seg 各跑 seeds 42/43/44，并同时执行标准 AP 与 `eval_citrus_challenges.py`。运行命令见 `1_SEVER/code/ultralytics-main-new/20260830_CITRUS_G0839_SERVER.md`。

正式协议固定 `amp=false`，因为 S/B grouped-clean 结果均为 AMP-off。旧 G10 同样是 `amp=0`，因此其历史高分不能归因于 AMP；当前没有同模型、同数据、同 seed 的 AMP on/off 成对结果，任何 AMP 精度结论都必须等待单独对照。

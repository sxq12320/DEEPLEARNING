# 柑橘基线对比：服务器环境安装与批量运行

> 版本：2026-09-16。配合 `对比实验方案.md`（实验设计）与
> `全基线对比一键运行指南.md`（单族启动器）使用。
> 主入口：`run_comparison_batch.py`（E 系列风格：固定协议、种子分块随机顺序、单卡串行、ledger 溯源）。

## 1. 基线矩阵（顶会出处，新旧结合）

| 编号 | 模型 | 族 | 出处 | 角色 |
|---|---|---|---|---|
| S0 | U-Net + marker Watershed | unet | MICCAI 2015 | 语义转实例辅助基线 |
| B3 | Mask R-CNN R50-FPN | torchvision | ICCV 2017 | 经典两阶段 |
| B5 | SOLOv2-Light R18-FPN | mmdet | NeurIPS 2020 | 无框位置式实例分割（期刊增强） |
| B0 | YOLOv8n-Seg | yolo | 2023 | 旧代轻量 YOLO |
| B2 | RTMDet-Ins-tiny | mmdet | 2023 | 非 YOLO 轻量一阶段 |
| E0 | YOLO11n-Seg | yolo | 2024 | **主消融基线** |
| B4 | RF-DETR Seg Preview | rfdetr | 2025 | 端到端 Transformer |
| B1 | YOLO26n-Seg | yolo | 2025 | 当前 YOLO 强对照 |
| 可选 | YOLO11s / YOLO12n / mmdet Mask R-CNN / DeepLabV3+ / SegFormer-B0 | — | ECCV 2018 / NeurIPS 2021 | 按需 `--only` 追加 |

时间跨度 2015→2025，覆盖 CNN/Transformer、单阶段/两阶段/无框/语义转实例四条路线，符合
`AGENTS.md` 的最少跨系列比较要求（SOLOv2 已占用 CondInst/SparseInst 名额，不再重复加入）。

## 2. 服务器路径约定（默认值，均可 CLI 覆盖）

```text
/data/sxq/datasets/orange_yolo                          # 只读源数据（group-aware YOLO 划分）
/data/sxq/results/002_retrain/_prepared/citrus_prepared # 一次性转换的 yolo/coco/rfdetr/semantic 四格式
/data/sxq/results/002_retrain/<family>/                 # 各训练输出（yolo|mmdet|maskrcnn|rfdetr|unet_watershed）
/data/sxq/results/002_retrain/evaluation/               # 统一 COCO mask 评估输出
/data/sxq/results/002_retrain/_protocol/                # ledger.jsonl + implementation_sha256.json
/data/sxq/code/mmdetection                              # mmdetection v3.3.0 源码（官方 config + checkpoints/）
```

路径不同时用 `--source/--prepared/--workspace/--mmdet-root` 覆盖，不改常量。

## 3. 环境安装（推荐：每族一个 conda env）

`run_comparison_batch.py` 通过 `--python-<family>` 为每个族指定解释器，因此
**不必**把 mmcv/rfdetr/ultralytics 塞进同一环境——各用各的 env，一个队列串行驱动：

```bash
cd /data/sxq/code/baseline_choice

# 一键建全部 5 个环境（或只建一个：bash setup/install_server_envs.sh mmdet）
bash setup/install_server_envs.sh
```

脚本默认行为（都可用环境变量覆盖，见脚本头部）：

| env 名 | 内容 |
|---|---|
| `citrus-bl-yolo` | torch(cu124) + `pip install -e ../ultralytics-main-new`（8.4.x，含 yolo26-seg） + requirements-yolo.txt |
| `citrus-bl-mmdet` | **torch 2.4.1(cu124)** + mmcv 2.2.0 + mmdet 3.3.0 + requirements-mmdet.txt + clone mmdetection v3.3.0 |
| `citrus-bl-mrcnn` | torch + torchvision + requirements-torchvision-maskrcnn.txt |
| `citrus-bl-rfdetr` | torch + rfdetr>=1.3 + requirements-rfdetr.txt |
| `citrus-bl-unet` | torch + segmentation-models-pytorch + skimage/scipy + requirements-unet.txt |

注意两点：

- **mmcv 只有 torch ≤2.4.x 的预编译 wheel**。`citrus-bl-mmdet` 固定 torch 2.4.1+cu124；
  若服务器驱动要求更新的 torch，需要源码编译 mmcv（`MMCV_WITH_OPS=1 pip install -e` mmdetection），
  否则 mmdet 的 NMS/RoIAlign 不可用。
- 装 rfdetr 时**先装 torch 再装 rfdetr**，防止 pip 解析时把 torch 换成 CPU/其它 CUDA 版。

### 3.1 备选：单一大环境

若坚持用单一环境跑全部族（此时不需要 `--python-*`），请使用与 mmdet 兼容的组合：
python 3.10 + torch 2.4.1(cu124) + mmcv 2.2.0 + mmdet 3.3.0 + rfdetr + smp + fork editable。
冲突风险自担；不推荐。

### 3.2 预训练权重

| 族 | 权重来源 | 获取方式 |
|---|---|---|
| yolo | ultralytics 官方 `.pt` | 首次训练自动下载到 `baseline_choice/`；离线服务器请提前拷入该目录 |
| torchvision | torchvision COCO 权重 | 首次构建自动下载（`--initialization coco`） |
| rfdetr | 官方托管权重 | 模型初始化自动下载 |
| mmdet | OpenMMLab model zoo | **`setup/fetch_mmdet_checkpoints.py`（手动执行一次）** |
| unet 族 | ImageNet encoder | smp 初始化自动下载 |

mmdet 三个权重复制到 `mmdet_root/checkpoints/`（registry 的 `checkpoint_glob` 解析，
`train_mmdet.py --checkpoint` 注入，保证与其他族一样从官方 COCO 预训练出发）：

```bash
conda run -n citrus-bl-mmdet python setup/fetch_mmdet_checkpoints.py --mmdet-root /data/sxq/code/mmdetection
```

下载失败（无网）时按报错里的 model zoo 地址手动下载放进 `checkpoints/` 即可，glob 命中即生效；
不命中也能跑（退回 config 默认初始化，日志有显式警告，但正式对比建议补齐）。

conda run -n citrus-bl-yolo   python setup/preflight_check.py --family yolo

conda run -n citrus-bl-rfdetr python setup/preflight_check.py --family rfdetr
conda run -n citrus-bl-unet   python setup/preflight_check.py --family unet
conda run -n citrus-bl-yolo   python setup/preflight_check.py --family common \

全部 `FAIL=0` 再往下走；`WARN`（如 mmdet checkpoint 未下载、prepared 未生成）可接受。

## 5. 批量运行（单入口，串行单卡）

```bash
cd /data/sxq/code/baseline_choice

# 0. 干跑：只打印队列、协议、各环境解释器
python run_comparison_batch.py --suite smoke --dry-run \
  --python-yolo        /path/to/citrus-bl-yolo/bin/python \
  --python-mmdet       /path/to/citrus-bl-mmdet/bin/python \
  --python-torchvision /path/to/citrus-bl-mrcnn/bin/python \
  --python-rfdetr      /path/to/citrus-bl-rfdetr/bin/python \
  --python-unet        /path/to/citrus-bl-unet/bin/python
```

为免每次带 5 个 flag，可在 `~/.bashrc` 一次性 export：

```bash
export CITRUS_BL_PYTHON_YOLO=/data/sxq/miniconda3/envs/citrus-bl-yolo/bin/python
export CITRUS_BL_PYTHON_MMDET=/data/sxq/miniconda3/envs/citrus-bl-mmdet/bin/python
export CITRUS_BL_PYTHON_TORCHVISION=/data/sxq/miniconda3/envs/citrus-bl-mrcnn/bin/python
export CITRUS_BL_PYTHON_RFDETR=/data/sxq/miniconda3/envs/citrus-bl-rfdetr/bin/python
export CITRUS_BL_PYTHON_UNET=/data/sxq/miniconda3/envs/citrus-bl-unet/bin/python
```

（`conda run -n <env> python -c 'import sys;print(sys.executable)'` 可打印真实路径。）

正式流程（与 `对比实验方案.md` §3 一致）：

```bash
# 1. 冒烟：核心+期刊+辅助 8 个模型 × 2 epoch，验证数据转换/前向/反向/评估全通
nohup python run_comparison_batch.py --suite smoke --device 0 > bl_smoke.log 2>&1 &

# 2. 筛选：核心 6 模型 × 50 epoch，判定主基线（RTMDet vs YOLO11n，阈值 ±1.5 点）
nohup python run_comparison_batch.py --suite screen --seeds 42 --device 0 > bl_screen.log 2>&1 &

# 3. 正式：核心 6 + SOLOv2 + U-Net × 300 epoch，种子 42；中断后 --skip-completed 续跑
nohup python run_comparison_batch.py --suite formal --seeds 42 --device 0 --skip-completed > bl_formal.log 2>&1 &

# 主基线三种子复核（E0 YOLO11n-Seg；最终方法同此口径）
nohup python run_comparison_batch.py --suite formal --seeds 3407,2026 --only yolo11n_seg --skip-completed > bl_e0_seeds.log 2>&1 &

# 4. 统一 test 集 COCO mask 评估（已训模型，未训的自动跳过并记 ledger）
python run_comparison_batch.py --suite eval --skip-completed --device 0

# 5. 聚合论文对比表 → evaluation/comparison_table_test.{csv,md}
python run_comparison_batch.py --suite report
```

可选模型（`--only` 可跨 tier 直达）：`--only yolo11s_seg`、`--only deeplabv3plus`、`--only segformer_b0`、
`--only mask_rcnn_r50`（mmdet 版交叉验证）等，配合 `--suite formal|all` 使用。

## 6. 输出与溯源

- 训练输出：`results/002_retrain/<family>/<E|SMOKE|S50>_<family>_<baseline>_seed<N>/`（best 权重 + run_metadata.json）
- 评估输出：`results/002_retrain/evaluation/<run>_<split>/metrics.json` + `predictions.coco.json`
- 溯源：`_protocol/ledger.jsonl`（队列、命令、解释器、git 状态、开始/完成/失败事件）
- 实现快照：`_protocol/implementation_sha256.json` 哈希本脚本 + registry + `scripts/*.py`。
  **快照变化即拒绝同目录混跑**，防止不同口径的结果进同一张表。若升级本套件后首次运行报
  `Implementation changed`：确认旧输出仅为 smoke/screen（可弃）→ 删除 `_protocol/` 与旧运行目录重来；
  若已有正式结果 → 把 `--workspace` 指到新目录，保留旧表。

## 7. 注意事项

- RF-DETR 仅有 Seg Preview @312：表中加脚注，延迟不与 640 模型直接比。
- U-Net/DeepLabV3+/SegFormer 一律写 `+ Watershed`：语义输出经分水岭转实例，不单独称实例分割。
- 测试集在方法定稿前不反复查看：smoke/screen 只评 val，formal 之后才跑 `--suite eval`（test）。
- 每族失败事件进 ledger（`failed`），修复后用 `--skip-completed` 续跑；`--fail-fast` 出错即停。
- GPU 时间量级（300ep、单卡）：YOLO 3–6h/模型；Mask R-CNN/SOLOv2 8–15h；RF-DETR 10–20h；U-Net 2–4h。
- Windows 本地与服务器共用同一入口；`os.name` 自动选路径，`--python-*` 同样适用。

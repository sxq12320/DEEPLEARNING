# 柑橘幼果实例分割跨范式对比实验方案

> 版本：2026-09-09
> 适用范围：论文一（轻量化未成熟柑橘实例分割）的 baseline 对比。
> 主批量入口：`run_comparison_batch.py`（E 系列风格：固定协议、种子分块随机顺序、单卡串行、ledger 溯源）。
> 本文档与 `3_研究生/柑橘套袋视觉_完整研究执行计划.md` 第 3、7 节保持一致。

## 1. 实验目的

1. 建立覆盖不同范式（旧代/当前 YOLO、非 YOLO 一阶段、经典两阶段、当前 Transformer、无框位置分割、语义转实例）的公平对比表，回答"提升不是只来自代际更新或框架差异"。
2. 通过 50 epoch 筛选确认主消融基线（YOLO11n-Seg vs RTMDet-Ins-tiny），避免"又一篇改进 YOLO"的同质化质疑。
3. 为最终方法（E 系列改进模型）提供同协议、同数据、同评估的参照系，使涨点可归因。

## 2. 对比矩阵

### 2.1 核心对比（必做，6 个）

| 编号 | 模型 | 族 | 角色 | 目的 |
|---|---|---|---|---|
| B0 | YOLOv8n-Seg | yolo | 旧代轻量模型 | 证明提升不只来自代际更新 |
| E0 | YOLO11n-Seg | yolo | **主消融基线** | 与每个改进逐项比较 |
| B1 | YOLO26n-Seg | yolo | 当前 YOLO 强对照 | 回答"为何不比较最新 YOLO" |
| B2 | RTMDet-Ins-tiny | mmdet | 非 YOLO 轻量一阶段 | 必做的轻量公平对照；主基线候选 |
| B3 | Mask R-CNN R50-FPN | torchvision | 经典两阶段 | proposal-based 标准基线（Torchvision 版最稳） |
| B4 | RF-DETR Seg Preview | rfdetr | 当前 Transformer | 端到端实例分割路线对照 |

### 2.2 期刊增强与辅助（第二批）

| 编号 | 模型 | 族 | 角色 |
|---|---|---|---|
| B5 | SOLOv2-Light R18-FPN | mmdet | 无框、按位置生成实例 mask 的对照（期刊增强；加入后不再同时加 CondInst/SparseInst） |
| S0 | U-Net + marker Watershed | unet | 语义前景 + 传统分离的辅助基线（表中写 `U-Net + Watershed`） |

### 2.3 可选（最后补）

| 编号 | 模型 | 说明 |
|---|---|---|
| B6 | YOLO11s-Seg | 同家族精度上界参考 |
| B1b | YOLO12n-Seg | 已有权重可直接加入 YOLO 族 |
| B3b | Mask R-CNN R50-FPN (MMDetection) | 与 Torchvision 版交叉验证 |
| S1 | DeepLabV3+ 或 SegFormer-B0 + Watershed | 二选一，语义路线补充 |

## 3. 三阶段执行流程

```text
smoke（2 epoch，全部模型，1 种子）
  → 验证环境、数据转换、构建/前向/反向、评估脚本全部打通
screen（50 epoch，核心 6 模型，种子 42）
  → 主基线判定（见 §5）；输出筛选表
formal（300 epoch，核心 6 + SOLOv2 + U-Net）
  → 基线模型：种子 42；主基线 E0 与最终方法：种子 42/3407/2026，报告均值±标准差
eval（统一 test 集 COCO mask 评估）
report（聚合生成论文对比表）
```

### 3.1 主基线判定规则（screen 阶段）

- 若 RTMDet-Ins-tiny 的 Mask mAP50-95 与 YOLO11n-Seg 相差 ≤1.5 点、训练稳定且难例表现更好 → 与导师讨论切换主基线；
- 若落后 >1.5—2.0 点或框架适配明显拖慢进度 → 维持 YOLO11n-Seg 为主消融基线，RTMDet 作为必做横向对照；
- 筛选结果出来前，不同时为两个框架开发改进模块。

## 4. 统一公平协议

### 4.1 数据

- 所有模型使用**完全相同的 group-aware 划分与类别定义**（`prepare_dataset.py` 一次转换，YOLO/COCO/RF-DETR/semantic 四种格式同源）；
- 主精度表统一 640 输入；RF-DETR 使用其官方支持的最近分辨率（当前包仅暴露 Seg Preview @312，表中须加脚注，不与 640 模型直接比速度）；
- 测试集在方法定稿前不反复查看；smoke 只用 val 评估，formal 才用 test。

### 4.2 训练

| 项 | 设置 |
|---|---|
| YOLO 族 | 300 epochs，imgsz=640，batch=4，AdamW，lr0=0.001，weight_decay=0.0005，patience=100，**amp=False**，dropout=0，官方 COCO 预训练，seed 锁定 |
| MMDetection 族 | 官方 config 默认优化器与 lr（公平原则：不强迫跨框架同一优化器），300 epochs，官方 COCO 预训练，val_interval=5 |
| Torchvision Mask R-CNN | SGD lr=0.005，momentum=0.9，weight_decay=0.0005，COCO 初始化，detections_per_image=50（覆盖单图最多 35 实例） |
| RF-DETR | 官方包默认（lr=1e-4，EMA，multi-scale），batch=2×grad_accum 4 |
| U-Net | 合并全部实例为二值前景训练；分水岭阈值只在 val 集调优，test 不单独调参 |

### 4.3 评估

- 统一 `scripts/coco_utils.py` 的 COCO mask 评估器：Mask AP50-95 / AP50 / AP75 / AP-small/medium/large、mask P/R/F1（IoU=0.5、score=0.25）、端到端延迟（batch=1）；
- U-Net 同时报告语义指标（Dice、mIoU、Boundary F1）与分水岭转实例后的同一套 Mask AP；
- Params/GFLOPs/显存/batch=1 延迟在同一硬件、同一精度模式下重新测量；
- PR 曲线 Recall=1 处的归零端点按评估实现哨兵点解释，不作为模型缺陷证据。

## 5. 成功判据与报告口径

1. 核心 6 模型 + SOLOv2 + U-Net 全部完成 formal + test 评估，进入同一张对比表；
2. 主基线 E0（YOLO11n-Seg）三种子均值±标准差作为改进模型的参照线；
3. 最终方法需在同表内优于全部核心基线，且满足执行计划 §7.5 的"轻量化+高精度"联合判据；
4. 表中每个数字可追溯到 `runs/evaluation/<run>_test/metrics.json` 与 ledger 事件。

## 6. 运行方式（Windows 本地 / Linux 服务器同一入口）

```powershell
cd E:\mastercode\1_SEVER\code\baseline_choice

# 0. 干跑：只打印队列与协议，不训练
python run_comparison_batch.py --suite smoke --dry-run

# 1. 冒烟：全部模型 2 epoch（先 core 可 --only）
python run_comparison_batch.py --suite smoke

# 2. 筛选：核心 6 模型 50 epoch、种子 42
python run_comparison_batch.py --suite screen --seeds 42

# 3. 正式：核心+期刊+辅助 300 epoch（中断后加 --skip-completed 续跑）
python run_comparison_batch.py --suite formal --seeds 42 --skip-completed
# 主基线三种子复核：
python run_comparison_batch.py --suite formal --seeds 3407,2026 --only yolo11n_seg --skip-completed

# 4. 统一 test 评估（已训模型）
python run_comparison_batch.py --suite eval --skip-completed

# 5. 聚合报告（CSV + Markdown 论文表）
python run_comparison_batch.py --suite report
```

单卡串行执行；`--device 0` 指定物理 GPU；`--only a,b,c` 过滤模型；`--fail-fast` 出错即停。
每次运行写入 `_protocol/ledger.jsonl`（队列、命令、Git 状态、开始/完成/失败事件）与实现快照
（脚本+配置 sha256）；快照变化会拒绝在同一输出目录混跑，防止把不同口径的结果放进同一张表。

## 7. 注意事项

- **不要**把 RF-DETR @312 的延迟与 640 模型的延迟直接比较（表中加脚注）；
- **不要**把 U-Net 的语义输出直接称为实例分割，表中写 `U-Net + Watershed`；
- 历史 `001`–`003` 及 G/T 等高点来自不同数据版本或训练设置，不进本表；
- 若某模型训练失败，ledger 记录 `failed`，修复后用 `--skip-completed` 续跑，不删除已有结果目录；
- GPU 时间估计（300ep、941 张量级、单卡）：YOLO 族每模型约 3—6 h；Mask R-CNN/SOLOv2 约 8—15 h；RF-DETR 约 10—20 h；U-Net 约 2—4 h。排期时先 core 后扩展。

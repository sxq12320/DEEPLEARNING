# E V5：基于 V4R 证据的尺度—掩膜细节—区域区分实验

2026-09-11。已实现并完成本地功能验证；**尚未进行 V5 的正式训练，不能承诺涨点**。

## 1. 先说结论

V4R 的收益是局部的，不是全面胜出。V4R05 值得作为下一轮轻量控制：保留最深层 EV3DeepStage、非对称颈部、16 通道 P2 细节与有下限的掩膜质量排序；不默认保留收益不稳定的高通细节修正。

现在最直接的证据支持继续研究输入尺度，并在扩大目标后抑制背景误检。V5 将三个因素拆成完整的 2×2×2 对照，避免同时换主干、优化器和输入后无法解释结果。八个实验配置对应四种模型图，每种图分别接受两种输入方案；不是虚称八种完全不同的架构。

## 3. PR 不是“置信度 0.85 时精度归零”

已同时检查 V4R05 的 MaskPR_curve.png 与 MaskP_curve.png。PR 图横轴是 **Recall**；真正的 Precision–Confidence 图在置信度约 0.89 时显示精度接近 1，而不是零。

当前 `ultralytics/utils/metrics.py:compute_ap()` 显式追加 `(最大实际召回, 0)` 和 `(1, 0)`，再计算包络/插值。因此末端贴地包含“模型未达到该召回范围”的绘图补零。到达末端之前，低置信度候选中误检增加也会使精度真实下降。不能通过平滑曲线、删难例或把尾部抬高来“解决”。

V4R05 已上传配对评估中，conf=0.001 时整图最大掩膜召回约 **89.04%**，trustedmask 切片约 **94.18%**。这和图中约 0.85 的拐点不是同一个量。配对评估采用长边 640 的公共掩膜栅格，与官方每轮 mask_ratio=4 评估的 AP 数值不能混用。

V5 保留原始官方 AP 实现。新评估另存 `empirical_mask_pr`，按实际预测分数累计 TP/FP，不补零，并记录 Rmax、P≥90% 的召回、重复/背景等错误桶。它是诊断曲线，不替换官方曲线或指标。

### 极小目标的直接证据

以下是 V4R05 同权重、同验证集、conf≥0.25、Mask IoU≥0.5 的匹配数。面积来自公共长边 640 栅格，不是原图面积，也不是 COCO APsmall。

| 可见掩膜面积 | GT 数 | 整图检出 | 原有切片 trustedmask 检出 |
|---|---:|---:|---:|
| <16 px² | 4 | 0 | 0 |
| 16–63 px² | 55 | 0 | 16 |
| 64–255 px² | 102 | 25 | 55 |
| 256–1023 px² | 286 | 206 | 235 |
| ≥1024 px² | 602 | 584 | 592 |

极小目标合计 161 个：25→71；<64 px² 的 59 个仍有 43 个漏检。这支持输入尺度是瓶颈之一，但尚不能分清每个失败分别来自分辨率、遮挡、分类、定位还是掩膜质量。

deep8 四组配对的切片极小目标匹配数分别 +12、+12、+8、+4；quality 四组配对的公共栅格 AP50–95 都提升，但匹配数变化为 −4、−8、+6、−2。质量排序不能替代候选召回。detail 的影响正负都有，不能把“高频”直接等同于“果实”。

V4R05 切片固定阈值错误桶有 298 个背景型误检；它们不是已人工确认的 298 片叶子。果叶颜色混淆仍是合理假设，需要难例复核，不能仅凭单类混淆矩阵证明。

## 5. V5 实际改动

**主干与颈部：**沿用本轮轻量候选 V4R05，而非回到未改动 YOLO。最深 stage8 使用 EV3DeepStage；保留浅层预训练结构、SPPF/C2PSA 和非对称 P3→P4 融合，不重建昂贵的完整回流 P5。此次没有再更换整个主干，因为 V3 两个深层同时替换并未给出可靠的整图 AP 优势。

**T：多尺度输入。**控制保持 50% 整图 +50% 边长比例 .6 的局部图；新方案为 50% 整图 +25% .6 +25% .4。正常尺寸的 .4 局部图采用覆盖整图的 3×3 重叠网格，不看 RGB 内容、GT 中心或先验热图。每次仍只抽一个视图、每轮原图抽样次数相同。相对 .6，.4 视图里同一目标边长约再放大 1.5 倍，不保证所有目标都可恢复。

**R：掩膜专用细节路由。**原有 P2 细节→P3 候选中继保持不变；另外用窄通道语义上下文对掩膜细节做一次残差适配，再注入原型分支。避免同一份未经任务适配的细节被两个消费者强行共用。只有 16 通道普通卷积，不增加完整 P2 检测塔。共享特征仍接受两种任务梯度，因此不是完全梯度解耦；小幅有界残差也不是闭环稳定性证明。

**C：训练期区域区分。**由已标注的可见实例掩膜并集提供前景监督；邻域环只取所有果实以外的背景，包含叶子、树枝等，并非叶片专属标签。损失为 `0.05 × (前景均衡BCE + 背景均衡BCE + 0.5×邻域背景BCE + 0.1×区域原型对比)`。8 维投影、温度 .2、每类最多128个困难查询；没有凸包、圆形约束、形态学闭合或推理 GT。辅助分类器和投影只在训练时执行，推理不计算。

C 的并集辅助不能承担实例分离：原有逐实例掩膜损失仍负责分开相邻果实。它也可能带来过平滑或小目标梯度不足，故保留独立消融，并新增 split/merge 的保守重叠代理统计；这些代理不是人工金标准。

**优化与评分：**所有臂继续使用固定 AdamW、lr0=.001、AMP=False、cache=True 等；已有 SMC/SMCAO 本轮不混入。原质量分支 gain=1、score floor=.5 不变。这样能回答结构/输入/监督是否有用，而不是再把不同优化器混成一个“架构提升”。新增同时保存 `best_mask50.pt`，不再只按 AP50–95 留模型。

## 6. 数据限制与文件保护

本地 `data/orange_yolo` 为676张训练图、4324实例；61张图中90个多边形几何无效。旧裁剪器遇到无效源多边形或无法用单多边形表示的交集时，跳过该局部视图而保留原图。这会降低实际切片覆盖率。详见 `data_feasibility.json`；尚未核实这些本地标注与服务器内容逐字相同。

本轮没有修复、删除或改写原始标注/图像，也没有按小目标尺寸过滤。V5 保留旧裁剪契约，生成独立派生缓存并记录 fallback，不偷偷改变标注语义。`loaded_data_summary.json` 记录各尺度实际窗口及缺失尺度的源图数量。

## 7. 如何运行

上传更新后的整个 `1_SEVER/code/ultralytics-main-new`，不要只上传 YAML。打开 `RUN_CITRUS_E_V5.py`，改这几项：

```python
DATA = "/data/sxq/datasets/orange_yolo/data.yaml"  # 你的真实数据路径
DEVICE = "1"                                   # 物理卡号
SUITE = "all"
EPOCHS = 300
DRY_RUN = False
```

选择已配置的服务器 Python 环境，点击 VSCode 右上角三角形，或在代码根目录执行：

```bash
python RUN_CITRUS_E_V5.py
```

前台同进程顺序训练，不使用 nohup、不并发跑模型、不做 GPU 占用保护。每个模型仍有4个 DataLoader worker，不等于4个独立训练。完成的实验跳过，半途输出不覆盖；Ctrl+C 停止且不启动下一模型。若从其他程序继承了冲突的 CUDA_VISIBLE_DEVICES，换干净终端并核对环境，避免卡号被重映射。

默认输出 `/data/sxq/results/E_V5/CITRUS_EV5_ALL_300EP`。模型顺序按 seed 固定打乱，不一定先跑00。修改协议或源码后使用新的输出目录，避免混合运行。

只跑一组可设置 `ONLY = "V5_05_fine_region"`；轻量对照建议先00、01、03、05，再看是否需要R。默认仍是全部八组，不额外加入原生 YOLO 重训。

全部 YAML 位于 `0_orange_yaml/E_V5_series/`。`YOLO(yaml).train(...)` 可直接构建模型，并自动选择对应损失；**仅用 YAML 不会自动切片或固定训练超参**。复现实验输入必须用本系列入口，或明确传入相应 Trainer/派生 data.yaml，不能把普通训练当成同一个实验。

依赖沿用现有工程与 `requirements-citrus-e.txt`；没有 Mamba、额外 CUDA 扩展或新大型模型包。不要为运行这些配置随意升级官方 ultralytics 覆盖本地修改。

## 8. 看哪些结果，如何决定保留

每轮官方验证始终是原验证整图。`best.pt` 保留框+掩膜综合选择；`best_mask.pt` 按 Mask AP50–95；`best_mask50.pt` 按 Mask AP50。三者对应轮数分别记录，不串用。

训练后，对每组的同一 `best_mask.pt` 都进行 coarse(.6) 与 fine(.4) 两个预算的配对评估，分别写入 `paired_coarse_eval/paired_metrics.json` 和 `paired_fine_eval/paired_metrics.json`。每份包含 global/fixed_box/crossmask/trustedmask、实测耗时、极小果匹配、背景/重复错误、原始 PR 点和 split/merge 重叠代理。切片训练收益、切片推理收益、合并方法收益要分开报告。

保留条件不是曲线看起来圆滑，而是同协议下 AP50 与 AP50–95、小果召回和 P≥90% 召回的实际变化，并检查背景误检、相邻果实例分离及总延迟。若 fine 只靠更高推理开销涨点，不能称为单模型免费提升；若 C 抑制背景同时降低小果召回，应减弱/放弃，而不是凭叙事保留。

单 seed 的零点几提升属于筛选线索。最终控制与入选方法应各跑42/43/44三个 seed，以均值±标准差报告，并保留未用于选择模型的正式测试集。

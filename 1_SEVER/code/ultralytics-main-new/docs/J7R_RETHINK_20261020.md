## 5. 新V7的唯一主问题

**让真实高分像素更早进入完整识别路径，在接近原生预算下，是否比只有低分输入及其插值更好？**

主候选 J120：原图产生对齐G640/H1280；高图经两次空间重排与窄PW/DW投影，
在原生stem输出（320网格）处读入；随后复用完整原生C2–C5、PAN和Segment。
这是双观察、单成熟语义主线，不是两套完整骨干。P3/P4/P5均保留。
相对J118改变的是整个证据接口，不宣称严格证明“仅注入位置”产生效果。

原生24个语义层按共同seed复制初始化；branch零起点门控，初始输出等于原生。
raw/pseudo对照整个分支初值相同，超参与评测不动。
没有添加新损失、优化器、ROI候选、置信度乘分或巨大注意力模块。

### 数学只证明可以证明的部分

设高分子像素向量为p，Q=I−11ᵀ/4，则Q为正交投影：
Q²=Q、Qᵀ=Q、rank(Q)=3、||Qp||≤||p||。这只消去块内共同分量，不代表恢复信息或区分果/叶。
若U是后续重排、A是可学习PW，则 A U Q p = (A U Q U⁻¹) U p。
因此任意raw首层可表示phase受约束首层；Q没有新增函数表达能力，只可能改变归纳偏置。
**所以J120 raw是主候选，phase仅可删的实验，不是所谓底层突破。**

readout实际为：
E = DW3(PW1(unshuffle2(P)))；
U = Expand(DW3(PW1(concat(PW1(S),PW1(E)))))；
S' = S + tanh(a) ⊙ U。
a初始0保证初始前向等价；a有梯度通路但不保证每个样本梯度非零；
第一步支路内部梯度为零是预期，后续门控开启后再学习。
48→16压缩有损，后续仍下采样，不能称“无损小目标保留”。

## 7. 如何训练

整体上传最新 `code/ultralytics-main-new`，不要只拷贝runner或YAML。
编辑根目录 `RUN_CITRUS_J7R.py`：

```python
DATA = "/你的实际数据集/data.yaml"
DEVICE = "1"                 # 物理GPU；可改0
SUITE = "policy"             # 默认先J119、J116
EPOCHS = 300
PROJECT = "/你的结果目录/J7R_新的运行编号"
```

VSCode选正确Python，打开此文件点右上角运行即可；或：

```bash
python RUN_CITRUS_J7R.py --dry-run
python RUN_CITRUS_J7R.py
```

dry-run只构建统计，不检验数据集/训练环境。服务器首次将EPOCHS改1–3并用新的PROJECT短测，
成功后再改300和另一个新PROJECT。没有nohup、GPU占用检查、数据指纹确认。
原有完成结果不覆盖，部分运行不静默重跑；Ctrl+C终止当前及后续队列。

控制组结束后：

- 若paired控制明显变差，先检查数据流程，暂不消耗后续结构算力。
- 决定继续时 `SUITE="evidence"` 批量J118/J123/J120。
- 只有raw证据有净收益，再选择 `SUITE="phase"`；不把它当默认最佳网络。
- 明确想一次跑前两块时可选 `SUITE="priority"`，共5组，不会自动暂停审阅。
- `ONLY="J120"` 可单独训练；`ONLY`非空优先于SUITE。

固定：AMP=False、cache=True、scratch、AdamW lr0=.001、weight_decay=.0005、imgsz640、
batch16/workers4、seed42筛选、EV6 /2评测。最终方法和控制用[42,43,44]；不在test选结构。
配置、源文件摘要、初始共同权重、第一批图/标签摘要、选择权重和原始PR都会保存。
默认formal路径在本地没有文件，须填写服务器实际路径，不会悄悄用旧数据。

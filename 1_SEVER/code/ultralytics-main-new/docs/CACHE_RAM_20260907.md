# 2026-09-07：统一启用 RAM 图像缓存

按用户明确要求，活动工程 `1_SEVER/code/ultralytics-main-new` 内的前台 RUN 入口、全部系列批量脚本、
独立柑橘训练脚本，以及当前 Ultralytics 默认训练配置，均默认 `cache=True`。
CLI 默认 `--cache ram`，也接受 `--cache True`；它们均对应 RAM，不是显存或磁盘缓存。

固定协议已切换到 `protocols/citrus_paper1_formal_v2_ram.yaml`，仅改变训练参数中的 cache。
AMP=False、优化器、学习率、增强、batch、workers等保持不变。旧v1协议和已完成结果保留原样，
历史文档中关闭cache的描述是旧实验配置，不再是新运行默认值。

使用方法：上传更新后的整个代码目录，仍运行原来的RUN文件。正在运行的进程不会自动生效。
新实验应换一个未使用的PROJECT目录，例如原路径末尾加 `_RAM`，避免和旧协议结果混合；
既有源码/协议保护会拒绝在旧project中悄悄换设置。这次未擅自更改你的数据路径或输出路径。

第一次启动需要读取图像建立内存缓存，启动阶段未必更快。缓存能减少后续重复读盘/解码，
不能加速模型算子本身；内存不足导致换页时还可能更慢。当前数据加载器保留内存容量预估：
不足时警告并禁用缓存，而不是强行占满。日志中的 `Caching images (... RAM)` 可用于确认实际启用。

当前Ultralytics还会提示RAM缓存可能带来非确定性。没有关闭这个警告，也没有改动seed或deterministic。
后续模型对照应统一使用v2设置，不能预先承诺与旧cache=False实验逐位一致或精度完全不变。

修改范围不包括历史结果的args.yaml、旧协议快照、历史归档及第三方代码库；不把GPU empty_cache、
supports_cache能力标志、pytest临时缓存等不同含义的cache统一乱改。

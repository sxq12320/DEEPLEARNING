# Citrus I V2：一致性优先的极小目标候选恢复

## 结论先行

I V1 尚未证明“双原型”有效。旧泄漏划分、单 seed、fine 切片评估下，I07 的 mask AP50-95 为
77.867%，只比重放锚点 I01 的 77.811% 高 0.056 个百分点；I04 主假设反而低 0.677 个百分点。
因此 I V2 不继续堆叠解码器，而把干预前移到**候选生成**：先修正训练时极小框尺寸判定的不一致，
再用可单独裁决的 P2 候选尺度验证“极小果实是否在 P3 之前已经消失”。

这些数字只解释历史实验，不能作为正式论文结论。I V1 使用旧 `orange_yolo` 划分；该划分已有
123/303 组跨 split 泄漏。正式比较必须在 `orange_yolo_grouped_dedup_20260820` 上重新运行同协议基线、
候选模型，并对最终模型使用 3 个 seed。

## I V1 证据复核

| 模型 | fine Mask AP50 | fine Mask AP50-95 | R@P≥0.90 | 最大召回 | tiny 匹配 | 延迟/ms |
|---|---:|---:|---:|---:|---:|---:|
| I07 sync-semlead | 89.586 | 77.867 | 81.221 | 96.854 | 92 | 328.6 |
| I01 V12 shared replay | 89.499 | 77.811 | **81.602** | 96.378 | **98** | 332.5 |
| I09 no-recognition | 88.903 | 77.680 | 81.316 | 96.282 | 92 | **302.1** |
| I04 sync main | 88.818 | 77.134 | 80.267 | 96.473 | 91 | 338.0 |

结论：I07 与 I01 的差异低于单 seed 可解释范围；I09 速度更快且接近最优，说明 recognition route
也必须保留关闭对照。双原型不能进入默认主线。

## PR 曲线的正确解释

Ultralytics 绘图会在 PR 数组末尾补 `(recall=1, precision=0)` 哨兵，因此最后一段竖直归零本身不是
模型故障，也不能通过改画图代码“修复”。真实问题仍存在：低阈值尾部 precision 约 3%，最大召回约
96%，说明仍有一批目标完全没有合格候选，同时降低阈值会释放大量叶片背景误检。后续必须报告：

- 原始未补点 PR、最大召回、R@P≥0.90；
- `<8 px`、`8–16 px`、`16–32 px` 分组召回；
- 背景误检、完全无候选漏检和仅低分候选漏检；
- Mask AP50 与 Mask AP50-95 的间隙、Boundary F1。

## 被修正的一致性问题

本地 `tal.py` 曾用 `wh < stride[0]` 判断尺寸，却用当前层 `stride[1]`（循环内保存为
`stride_val`）回填，产生不连续的 8/16 像素规则。I V2 改为判断和回填都使用同一 `stride_val`，与
上游 Ultralytics 当前实现语义一致。由于它会影响所有相关模型，I20 是**修正后的新锚点**，不能把
I20 与旧 I01 的差异写成结构涨点。

## 架构

I V2 保留 V12/I01 已验证的 16 通道持续高分辨率细节支路、共享 mask prototype、质量头和三尺度
预测塔。新增结构全部使用普通 Conv/DWConv：

1. `IV2P2Candidate`：从持续 P2 细节和 P3 语义构造 64 通道 stride-4 候选图。
2. `mode=0`：原始 P2 对照，检验仅增加候选密度是否有效。
3. `mode=1`：P3 语义门控局部高频残差，避免把所有叶脉都当成果实边缘。
4. `mode=2`：先用 7×7 depthwise 形成较宽语义参照，再调制 3×3 局部残差。
5. `IV2LargeSmallStage`：只替换 C3/C4 的 CSP 内部 mixer，保留下采样和外部投影，分别测试 C3、
   C3+C4；不把主干改动与 P2 强制绑定。
6. `SegmentCitrusIV2`：P2 塔追加在 P3/P4/P5 之后，已有塔索引不移动；不携带未经证明的 I V1
   双原型。

设计参考只取可检验思想：SET 的高频背景噪声观察、LSNet 的“大范围感知/局部聚合”分工、UGS 对
小框定位梯度不稳定的分析。没有复制其完整模块。SET 的二次训练前向、LSNet 的 Triton SKA、SFDNet
的 FFT/Mamba、BoltzFormer 的大型提示 Transformer 都因速度、环境或任务不匹配被排除。

本地官方仓库快照：SET `9208fbc`、LSNet `cbe737c`、SFDNet `7d0dd44`、BoltzFormer `c68c5f5`，
均位于 `C:/Users/33836/Desktop/github/`。SFDNet 仅按作者仓库/预印本处理，不能在论文中提前写成
已正式出版的对照方法。

# E V3：从 E V2 的失败与切片收益出发

2026-09-09。状态：新结构假设，不是已经涨点的模型。完整结果表在 [E V2 复核](E_V3_evidence/RESULTS.md)，可追溯记录在 [audit.json](E_V3_evidence/audit.json)。没有恢复用户删除的 reports，也没有修改原始数据或已完成结果。

## 一、哪些结论可以成立

共读取 results 下 196 份 CSV，去重后 182 份，读取错误 0。E V2 八个运行均完成 300 轮；本地 YAML 哈希与 completed.json 一致，验证文件列表一致，除模型/路径/名称外记录的训练参数一致。上传缺少 `_protocol`，不能声称已核实服务器全部 Python 源码的字节级版本。

同一最佳 Mask AP50–95 轮的官方指标如下，单位为百分数。这里不是切片推理 AP。

| 模型 | Mask AP50 | Mask AP50–95 | 相对 E20 的 AP50–95 |
|---|---:|---:|---:|
| E20 原结构＋固定切片训练对照 | 84.080 | 68.094 | — |
| E21 对比细节分支 | 83.230 | 67.551 | −0.543 |
| E22 共享上下文中心颈部 | 83.518 | 67.351 | −0.743 |
| E23 全面更换 Rep 主干 | 80.294 | 63.854 | −4.240 |

| E27 完整组合，引导切片 | 79.366 | 61.833 | −6.261 |

**必须承认：V2 没有产生比 E20 更强的整体架构。** E25 相对 E24 的 +0.514 不等于超过原对照；E21 单独加入对比细节反而下降，已经说明组合收益不能直接相加。

E20 预训练参数继承 97.80%，E23 62.36%，E25 46.05%。全主干替换同时改变表示与初始化，因此不能把 −5.507 完全归因于某一卷积算子。V3 保留浅层与原预测塔，并继续记录实际初始化继承率。

### 切片有用，但召回与误检必须一起看

以下全部来自同一个 frozen `best_mask.pt` 的独立成对评估；共同原图长边 640 掩膜栅格、conf≥0.25、mask IoU≥0.5。`trustedmask` 是固定切片＋跨视图掩膜抑制＋预先固定的内部边缘降权。

| E20 目标面积（该640栅格） | GT数 | 全图检出 | 切片检出 |
|---|---:|---:|---:|
| <64 | 59 | 0 | 17 |
| 64–255 | 102 | 30 | 54 |
| 256–1023 | 286 | 218 | 244 |
| ≥1024 | 602 | 584 | 591 |

切片后仍漏掉 143 个，其中 90 个面积<256，占漏检的 62.9%。超小目标问题获得了直接证据，不是仅凭 PR 曲线猜测。面积分组指可见掩膜面积，不是边长，也不是 COCO 原图 APs 定义。

E22 切片检出 tiny 80/161，E20 为 71/161；但背景误检 482 对 392、重复误检 44 对 24。相同高精度约束下 R@P≥90% 为 79.868% 对 80.267%，E22 并未更好。tiny 差值 +5.59 个百分点的图像 bootstrap 95%区间约 [0,10.83]，不能代替三个训练 seed 的复验。

E21 背景误检降到 285，但 tiny 检出降到 66/161：强行压背景也会压掉真正的小果实。当前不能把它当成必加模块。

引导切片 E27 没有超过同架构固定切片 E25 的官方精度，不足以证明引导器必要。V3 不再默认训练额外 guide。

### PR 与混淆矩阵的边界

已查看 E20 的 MaskPR、混淆矩阵及验证标注图。PR 前段仍保持较高精度；曲线末端归零包含本地 `compute_ap()` 在最大召回位置添加零精度哨兵、并延伸至 recall=1 的绘图/积分约定。它不等于真实模型在 recall=1 输出了零精度。

应当优化的是可达到的召回、R@固定精度和误检类型，不能通过改画图方式制造提升。E20 切片诊断的最大召回约 93.994%，R@P≥90%为80.267%；两者是不同阈值的量。

E20 上传的普通混淆矩阵是 847 个匹配、202 个漏检、208 个误检。代码沿用 detection validator 的**框 IoU**匹配，默认矩阵 IoU阈值0.45；它不是 Mask AP@0.5 的混淆矩阵，不能与上述906个切片掩膜TP直接拼接。

验证图可见绿果与叶片同色及明显尺度跨度。但“background FP”桶不区分叶片、枝条、未匹配碎片；尚未完成逐误检语义标注，因此不能声称颜色混淆已被单独量化或解决。

## 三、V3 的三个可验证因素

### B：选择性深层压缩

仅在 backbone 层6/P4、层8/P5，将 C3k2 内部的空间块改为 PConv＋通道混合；保留 CSP 投影尺寸/命名、浅层 C2/C3、所有主干下采样、SPPF/C2PSA。复用本仓库 G10 所用的 `FasterBlock` 思路，在小果实尚有空间细节的浅层不激进压缩。

这会更换主干的一部分，**不是整个全新主干**。新深层块仍需要训练，不能声称预训练表示完全等价。

### N：相位回流＋原尺度旁路颈部

保留逐级 C5→P4→P3 的空间 C3k2 细化。P3 回流到 P4 时，改用2×2像素重排＋1×1投影，减少该处计算；P4融合新增来自 backbone 原生C4的直接旁路，与 top-down P4 做归一化加权，再与P3回流拼接、经过原C3k2细化。原生C4初始权重约1.8%，避免开局突然大幅改变原语义路径。

这是对**信息路由、下采样和三输入融合**的改动，没有把所有尺度先压到同一个中心，也没有移除融合后的空间卷积。预训练P3/P4细化层与预测塔可以继续继承。

### Q：掩膜质量观测与评分

在三个原预测尺度增加16通道的小评分分支，以特征和mask系数预测低分辨率mask IoU，最终score=分类概率×预测质量。原框/分类/mask系数塔和Proto保留。辅助MSE在sem_loss中显示，权重1.0；基础box/seg/cls/dfl与超参数不变。

质量目标使用**预测框裁剪后的预测mask**，不是GT框；目标detach。辅助输入也detach，避免评分损失干扰原分割表示。每图最多64个正样本锚点参与这一额外损失，基础损失仍使用所有正样本。低分辨率标签中消失的实例ID不会引起剩余ID重编号错配；这些实例仅跳过不成立的额外IoU目标，不删原标签。

它只是低分辨率mask IoU的轻量代理，不是 Mask Scoring R-CNN 的完整ROI网络。它不会创造新的候选，单独未必改善极小果实召回，也不保证降低绿叶误检。必须用相同权重开启/关闭校准对照，并比较R@P≥90%，而不是只比较conf=0.25下的召回。

上述三个是实验因素，并非已经确立的“三大论文创新”。这也不是 PID/闭环控制器：没有被控系统、时间状态、误差反馈或稳定性证明，不能仅因使用“观测”一词就包装成自动控制创新。

E37 相对E30参数约少6.2%、计算约少2.0%。**此次是保精度优先的小幅压缩，不是大幅轻量化成果。** CPU、batch2、640、FP32的5次微基准中，E30训练前向+loss+反向中位749ms、E37为697ms；融合前向约183ms对184ms，不能声称推理加速。E35约821ms，存在额外开销。完整测量条件见cpu_profile.json；无CUDA本地不能保证3090速度，不包含数据加载、增强、优化器、NMS或多视图合并。

## 五、怎么运行

把更新后的 `code/ultralytics-main-new` 同步到服务器原项目，包含模块、loss、tasks、YAML和runner，不能只复制一个RUN文件。

打开 `RUN_CITRUS_E_V3.py`，设置这几行：

```python
DATA = "/data/sxq/datasets/orange_yolo/data.yaml"  # 你自己的已清洗数据路径
DEVICE = "1"                                   # 物理GPU编号
SUITE = "all"                                  # 八个模型
EPOCHS = 300
DRY_RUN = False
```

VSCode选择正确Python环境后点右上角三角形，或：

```bash
cd /data/sxq/code/ultralytics-main-new
python RUN_CITRUS_E_V3.py
```

当前Python进程前台串行运行，不使用nohup、不在本进程内并行。V3 入口已关闭跨进程单 GPU 锁和“GPU 已占用就退出”的保护，因此允许你在已有服务器任务共存时启动；多个任务共用同一张卡仍会降低速度，需由你自行安排。Ctrl+C停止且不会启动下一模型。完整运行有completed标记时自动跳过；半途目录不会被覆盖，需另选项目或明确恢复相应last.pt。不要求人工确认数据指纹，不替用户修改数据地址。缓存保持True，需要足够主机内存。

建议先在同一入口设置`SUITE="smoke"; EPOCHS=1`检查服务器，再改回all/300；PROJECT由suite/epochs自动区分，不覆盖。`priority`只跑E30–E33四个单因素对照，`combined`跑E34–E37。

全局训练超参数固定在 `protocols/citrus_paper1_formal_v2_ram.yaml`：AdamW，lr0=.001、lrf=.01、momentum=.937、weight_decay=.0005；640、batch16、workers4、cache=True、amp=False、seed42、dropout0、mask_ratio4、overlap=True、mosaic1、close_mosaic10。V3方法因素单列在`protocols/citrus_e_v3.yaml`，没有通过悄悄改AMP/学习率制造收益。

每轮仍在原全图val上评估；每个模型训练结束后自动用`best_mask.pt`做四种成对推理，位于该运行的`paired_sliced_eval/paired_metrics.json`。整体AP与切片AP请分别读，不混用。

单模型可直接 `YOLO("0_orange_yaml/E_V3_series/E37_full.yaml").load("yolo11n-seg.pt").train(...)`，模块和损失已在正常入口注册。**但普通train本身不会自动启用源图均衡切片采样**；要复现本系列完整输入协议，最简单是把RUN文件的`ONLY`设为`"E37_full"`。

对Q模型，另做同权重关闭校准的评估（单独输出，不能覆盖）：

```bash
python eval_citrus_e_v3.py --weights /你的运行/weights/best_mask.pt --data /你的数据/data.yaml --device 1 --output /新的输出/raw_quality --raw-quality
```

## 六、论文与代码依据、取舍

| 依据 | 实际查阅代码 | 迁移与限制 |
|---|---|---|
| [FasterNet，CVPR2023](https://arxiv.org/abs/2303.03667) | [官方 fasternet.py](https://github.com/JierunChen/FasterNet/blob/master/models/fasternet.py)，桌面github已有副本 | 部分通道空间卷积与通道MLP；不是越低FLOPs越快的保证；沿用本工程FasterBlock的SiLU/BN适配 |
| [EfficientDet，CVPR2020](https://arxiv.org/abs/1911.09070) | [官方fuse_features/build_bifpn_layer](https://github.com/google/automl/blob/master/efficientdet/efficientdet_arch.py) | 学习归一化融合和融合后空间细化；这里只给原生C4增加旁路，不声称新发明BiFPN |
| [Mask Scoring R-CNN，CVPR2019](https://arxiv.org/abs/1903.00241) | [官方仓库](https://github.com/zjhuang22/maskscoring_rcnn)，桌面maskiou_head的loss/feature_extractor | mask IoU监督与评分分离；改成一阶段低成本代理，原论文的COCO收益不能直接作为柑橘收益 |
| 桌面Plug-play中的DySample实现 | `(ICCV 2023) DySample.py`，偏移预测、pixel shuffle、grid_sample | 阅读后本轮不默认引入；高分辨率动态采样需单独实测显存、速度与插值影响，不因顶会标签就直接叠加 |

对未来实验的判定：先看官方Mask AP50–95是否超过E30，再看相同精度约束下tiny召回、重复/背景误检及实测总耗时。最终只保留Pareto有效模型；基线与候选各3个seed，用独立test作最后报告，避免持续针对val调参产生乐观估计。仍需补低对比/遮挡/接触果实子集，不能从当前统计直接声称解决颜色或拓扑难题。

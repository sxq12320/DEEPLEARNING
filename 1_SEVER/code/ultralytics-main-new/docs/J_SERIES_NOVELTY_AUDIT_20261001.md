# J 系列新意审查：不能把框图复杂度当作创新

结论：J11 是可实验的任务适配候选，**目前不足以声称已经形成三项强论文创新**。20组消融用于检验机制，不是20种独立新理论。已有代码保留作为工程对照，不为增加新意而继续增加未经验证的算子。

## 1. 借鉴来源与新意边界

| 当前设计 | 最近的相关思路 | 当前真实区别 | 不能声称 |
|---|---|---|---|
| 部分空间卷积 + 乘性门控主干 | FasterNet、GLU | 非CSP分层、窄通道、与独立细节解码协同 | 新发明部分卷积或门控；换掉C3k2就有充分创新 |
| 每尺度一次源竞争融合 | [ASFF](https://arxiv.org/abs/1911.09516) 已提出空间自适应融合 | 直接主干来源、先投影、保留P2细节、不做完整往返PAN | 首次用softmax对尺度加权；名称不同就是新算法 |
| 固定小记忆差分上下文 | Differential Transformer / LinearDiff | 16个池化位置、两个独立归一化流、零和读出 | 首次差分attention；能自动抵消真实叶片 |
| 分类软场景调制 + 原生细节掩膜 | PIDNet、既有E/I分路、细节分割工作 | 可见边界场景监督、分类受调制而框/系数直接支路保留 | 三分支就是PID；场景门控就实现人类视觉 |
| 有界tiny Dice、可见边界BCE | 常规Dice、boundary监督 | 按GT等贡献、小面积权重封顶、保留遮挡凹口 | 两个标准损失相加成为独立理论创新 |

这些区别能否构成方法贡献，要看同协议结果和更接近的消融；不能仅依赖“多个顶会思想相交”。数学部分目前证明的是代码所用算子的条件性性质，不是新的普遍定理。

## 2. 应凝练成一个任务问题，而不是三个模块名称

**在固定算力下，如何为极小可见果实保留有效空间支持，同时用结构与上下文排除叶片，又不填平遮挡凹口或粘连接触果实？**

这是分辨率、辨别性、可见拓扑和预算之间的联合问题。正式数据中短边<16px占17.39%、solidity<.85占17.61%、可见实例间隙≤2px占30.95%；三个子集必须分别报告，不能把总体AP的一个小提升解释为全部解决。

人类“先组织信息再辨认”的说法只作为设计启发；必须改写为可测的变量与失效情形。RGB派生灰度不增加传感信息，树叶也具有纹理和边缘，因此“灰度支路天然解决颜色混淆”不能作为论文论据。

## 3. 下一步先做失效归因，再决定真正的新机制

| 待检验假设 | 需要的诊断 | 若不成立就放弃什么 |
|---|---|---|
| H1：主要是输入缩小/候选漏检，不是mask轮廓恢复 | 同一权重global/coarse/fine；将FN按尺寸、遮挡分组；分别看Box R与Mask R | 不再仅提高原型分辨率来声称提升召回 |
| H2：主要是果叶结构辨别，而不是阈值/定位/标注协议 | 验证集FP/FN逐例小样本人工归因、强/弱对比子集；同一候选比较分类与mask IoU | 不再把单类fruit/background混淆矩阵直接当作“叶片类别混淆”证明 |
| H3：mask细节开销可由选择性计算替代 | J04/J05精度-延迟对照、真实GPU profiler、难例边界错误 | 不再默认全图stride2 decoder最优 |

GT框/GT区域的oracle实验如要做，必须单列为诊断上界，不作为部署方法的召回或AP。正式推理不得依赖GT。PR绘图补零先与实际最大召回区分；不以画出一条漂亮曲线作为机制成功标准。

## 4. 值得研究但尚未实现的结构升级

若H1/H3成立，研究**固定预算的高分辨率证据补偿**：保留现有普通候选退路，把高分辨率细节的计算用于真实低置信/高不确定支持，而不是把整幅P2都接成巨大密集头。选择性高分辨率计算已有 [QueryDet](https://openaccess.thecvf.com/content/CVPR2022/html/Yang_QueryDet_Cascaded_Sparse_Query_for_Accelerating_High-Resolution_Small_Object_Detection_CVPR_2022_paper.html)，因此“稀疏查询”本身不是我们的新意。

可能的任务区别需要同时满足：可见凹口/接触关系不被补全破坏；极小实例的高分辨率支持来自实际图像而非插值假细节；低置信误路由不硬删原候选；计算预算能通过真实裁剪/打包减少，而非只给dense特征乘一个稀疏门。

若H2成立，研究**同一实例的目标-邻域结构证据与预测一致性**，明确环状邻域的叶枝污染、被遮挡果实的非凸GT，以及颜色扰动的标签保持条件。不能把一个中心减去周围的算子直接包装成生物创新；也不能用“key去均值”这一softmax无效操作替代真正的对比机制。

这些是研究假设，不是已经运行的J网络功能。下一代是否增加动态ROI/局部解码，须先与传统ROI方法、QueryDet式选择性计算以及当前J05/J11比较。不为追求“颠覆”先引入复杂自定义CUDA、全图HRNet或多轮迭代反馈。

## 5. 图件应该揭示什么

总框图只说明数据流；机制图应画出对齐、源权重、差分读出、软调制与任务分路，并明确哪个是已有思想、哪个是任务适配。`J11_mechanisms.svg` 是当前实现的细化图，**不是靠多画几个盒子新增了创新**。

投稿前至少需要：同配方跨框架基线、主基线/最终模型三seed、非劣效性尺度/拓扑子集、真实端到端测速、明确最近相关工作区别。大幅涨点不是充分新意的替代品，参数少也不是识别能力的证明。

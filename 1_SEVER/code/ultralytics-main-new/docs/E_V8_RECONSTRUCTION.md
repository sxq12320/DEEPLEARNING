# E V8：基于 V7 和历史实验的结构重构

2026-09-14。状态：候选方案已实现；训练收益未知，不能承诺涨点幅度或期刊分区。

## 结论先行

V7 的证据支持保留细掩膜解码、可见边界/邻实例监督、切片混合训练；Copy-Paste 值得与几何监督组合验证。
不支持继续默认增加密集 P2、DCN 和频率注意力。V8 保留有效路径，减少一次 P4 重建，试验深层局部/上下文分工。
**不是换个系列名重跑十个随机模块，也不是十个完全不同的网络：10 个 YAML 包含必要的同结构训练消融。**

## 4. PR末端：真实漏检与零值补点要分开

当前 `ultralytics/utils/metrics.py::compute_ap()` 在 `recall[-1]` 添加 precision=0，然后补到recall=1。
因此曲线会在**最大实测召回**位置直降，并在尚未达到的召回区间画零线。00配对整图在conf≥.001条件下rmax约0.8875，与图形尾端位置相近；训练目录PNG可能来自best.pt而非配对评估的best_mask.pt，不能把两者当同权重严格对应。
这不是“置信度超过85%精度变零”，也不应通过延长高精度曲线到recall=1来美化AP。

尾部之前精度下降说明低分候选中误检增多；rmax不足说明当前分辨率、NMS、max_det、阈值和匹配条件下仍有漏检。
00在conf=.25共有1049−827=222个漏检，其中161−30=131个为极小果实（约59%）。这直接支持优先研究极小目标，但不证明其是唯一原因。
背景误检桶没有“叶片/枝条/真实漏标”语义标签，不能把全部背景FP直接称为颜色混淆。V8不修改历史指标或PR绘图代码。

## 5. V8结构与10个对照

**主干B**：仅在stride16的C4阶段用EV8ContextStage替代原C3k2整个stage。1/4通道做局部3×3，1/4用水平/垂直可分离卷积获得上下文，其余直接传递，再通道混合与有界残差。C2/C3浅层、现有深8、SPPF/C2PSA保留。
不是把完整FasterNet或LSKA原样装进去；局部/上下文分工是候选假设，不等于已证明具有形状偏置。

**颈部N**：保留原自顶向下P4/P3精炼，删除 `P3→stride2卷积→concat→C3k2→P4` 重建路径。新的P4读取原P4td、原生C4、池化后的原生C3，计算两个特征差，再以归一化门控产生一次窄通道残差纠偏。P4不再依赖已压缩的P3，P3自身路径不被重写。

与旧EV3NativeFusion的区别不是多一个名字：旧方案保留P3下采样及后续CSP，只额外混合native；本次移除该依赖和计算。与SAGE61区别是保留两个原空间精炼层和预训练权重。新颈部仍可能失败，因此05独立对照。

**掩膜头/监督**：复用已有SegmentCitrusEV7（关闭P2/DCN/PMCE）和EV7损失分派，不伪造一个新头名。phase细解码、16通道语义细节、quality floor=.5继续使用；09回到dense细解码。几何项仅监督可见实例边界/邻果，不补凸包、不强制圆、不补遮挡后区域。

现有额外边界项要求面积至少256输入像素且内部可解析，因此并非直接给所有极小实例加边界惩罚；小实例仍保留正常mask损失。极小召回主要由切片预算和保留细节路径承担，不能把几何组收益自动解释成极小召回改善。

## 6. 固定超参数与运行

上传整个最新 `1_SEVER/code`，不要只上传YAML。打开 `ultralytics-main-new/RUN_CITRUS_E_V8.py`：

```python
DATA = "/data/sxq/datasets/orange_yolo/data.yaml"  # 改成你实际清洗数据yaml
DEVICE = "1"
SUITE = "all"  # 10组；priority为00/03/04/05/08
EPOCHS = 300
DRY_RUN = False
```

VSCode选正确Python解释器后点击右上角三角形，或在项目目录运行 `python RUN_CITRUS_E_V8.py`。
同一Python进程前台顺序训练，没有nohup，没有占卡保护锁；Ctrl+C停止且不继续下一模型。
结果默认 `/data/sxq/results/E_V8/CITRUS_EV8_ALL_300EP`。队列使用固定seed打乱顺序，不并行跑十个模型。
不覆盖部分完成目录；已完成运行可跳过。若改模型源码，换新PROJECT。DATA只由用户指定，不新增数据确认交互。

固定：imgsz640、batch16、workers4、cache=True、AMP=False、AdamW、lr0=.001、lrf=.01、weight_decay=.0005、momentum=.937、dropout0、seed42、mask_ratio2、NWD0。
完整增强/优化/验证参数见 `protocols/citrus_paper1_formal_v2_ram.yaml` 和 `protocols/citrus_e_v8.yaml`，CP是显式编号例外。
这里没有再换优化器：否则难以辨别结构是否有效。所有模型从同一yolo11n-seg.pt开始，新层从声明初始化训练；加载覆盖率不同必须报告。
cache=True保留，但RAM缓存和GPU算子并不保证跨机器逐位可复现；RAM不足时先停止并单独确定新协议，不能偷偷改某一组。

单独模型可以通过官方 `YOLO(yaml)` 构建/加载；要复现本系列的混合切片训练、loss/CP设置及统一评估，推荐在入口填 `ONLY = "V8_08_structure_complete"`。
裸写 `YOLO(yaml).train(data=...)` 不会自动复制全部输入/增强协议，不能与批量结果当作同一实验。

## 7. 论文与下一步判定

先看00/03确认V7有效手段能复现，再比较04/05/06；若新结构不如03，保留03，不强行宣布08最优。
主要指标：统一评估的Mask AP50–95和AP50；辅以P≥90%时召回、极小命中、背景FP、实测端到端时间。细切片得分必须同时附切片数量与延迟。
03→08才检验结构在相同训练手段下的净贡献；08→09才检验细解码方式。训练曲线末20轮是稳定性描述，不是独立重复实验。

绿色混淆仍是待分型问题：在验证集固定难例清单，人工区分叶/枝/反光/遮挡/标注问题，再衡量颜色扰动下的相对退化，不能凭feature gate声称消除了颜色依赖。
遮挡深凹、接触果实需要solidity/凸包缺损、实例间隙和人工复核的split/merge分组；现有topology_proxy只是代理量。
若要提出三项论文贡献，应是经过实验支持的“尺度预算策略、保真且低冗余的特征路径、可见实例判别约束”，而不是十个模块名字；当前只有候选，尚不能写成已验证贡献。

文献与代码取舍详见 [来源与取舍](E_V8_REVIEW_20260914/来源与取舍.md)。科学证据审查决定了不更改PR以美化曲线、保留负面实验、固定超参；指南的模块组合思路只用来提出可证伪假设。

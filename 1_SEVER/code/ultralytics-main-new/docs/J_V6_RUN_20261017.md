## 1. 最简单的运行方式

将整个当前 `code/ultralytics-main-new` 上传服务器，不能只上传 YAML 或 RUN 文件。在 VSCode 中选择原有训练 Python 环境，打开 `RUN_CITRUS_J6.py`，按实际情况修改：

```python
DATA = "/data/sxq/datasets/orange_yolo/data.yaml"
DEVICE = "1"  # 物理 GPU 编号，不是重新映射后的逻辑编号
PROJECT = "/data/sxq/results/J/v6/CITRUS_J6_ALL_300EP_20261017_R2"
SUITE = "all"
EPOCHS = 300
SEEDS = [42]
ONLY = ""
RESUME = ""
PLOTS = True  # 默认保存PR、混淆矩阵等图；不静默关闭
```

之后点击右上角“运行 Python 文件”三角形即可。程序在当前 Python 进程中逐个运行，不使用 nohup，不启动后台训练子进程，也没有 GPU 占用保护锁或数据确认拦截。运行10个模型时只会同时训练其中一个。

命令行等价入口：

```bash
cd /data/sxq/code/ultralytics-main-new
python -u RUN_CITRUS_J6.py
```

`DEVICE="1"` 会在导入 torch 前设置 `CUDA_VISIBLE_DEVICES=1`，并将同一物理编号传给当前工程的设备选择函数。此时进程内部显示 `cuda:0` 是正常的，它映射到物理1卡。不要手动将传入训练的 device 改成逻辑0。

不应从已经初始化 CUDA 的 Notebook/交互会话执行此启动文件。请用新的 Python 进程运行，避免已有 CUDA 状态使设备绑定无效。

只有一张物理GPU的机器通常应设置 `DEVICE="0"`，不能照搬默认1卡。程序没有GPU占用锁，也没有跨进程项目锁：不要同时启动两份程序写入同一 `PROJECT`。

## 2. 先检查再长跑

只检查10个 YAML 的构建与参数量，不读取训练图像、不训练、不创建训练结果目录：

```bash
python -u RUN_CITRUS_J6.py --dry-run
```

先做一轮工程检查，仅运行主对照与完整模型：

```bash
python -u RUN_CITRUS_J6.py --smoke --only J90_global_control,J94_full
```

`--smoke` 强制一轮，并自动把项目目录改为 `PROJECT_SMOKE_1EP`，不会把一轮结果混入300轮项目。它不会改小图像尺寸，因此是真实640/1280双视图管线检查；CPU上运行不应视作GPU性能测试。重复 smoke 请换一个项目名，不覆盖上一次运行。

正式默认 `PLOTS=True`。有待训练任务时，程序会在训练开始前实际导入 Matplotlib/pyplot 预检绘图依赖；若与NumPy不兼容，明确报错并停止，不自动pip、不静默关图。`--dry-run`不需要通过这个绘图预检。

仅当明确接受“本次不检验绘图”的工程检查时，可使用：

```bash
python -u RUN_CITRUS_J6.py --smoke --no-plots --only J90_global_control,J94_full
```

该选项记录为 `plots=False`，不改变EV6匹配/AP计算，但不会验收PR、混淆矩阵或标签绘图。不能把无图smoke描述成绘图已通过。默认正式任务仍然保存图。

若需要50轮筛选，明确使用新目录：

```bash
python -u RUN_CITRUS_J6.py --suite screen --epochs 50 \
  --project /data/sxq/results/J/v6/CITRUS_J6_R2_SCREEN_50EP_01
```

随后300轮使用不同项目，而不是从50轮终止的 `last.pt` 冒充相同学习率调度的300轮训练。直接点击三角形的默认任务仍是全10臂、300轮。

## 3. 10个模型与正确的比较关系

YAML 全部位于 `0_orange_yaml/J_V6_series`，并登记于 `0_orange_yaml/MODEL_INDEX.csv`。头部参数与 YAML 内 `citrus_j6` 开关必须同步；测试会核验它们，实际构造参数以 head args 为准。

| 模型名 | 相对改变 | 建议比较 |
|---|---|---|
| J90_global_control | 标准 YOLO11n 主体；关闭高分辅助路径，保留同一数据与验证适配器 | J91 vs J90：整套高分共享/发现/局部分割是否有价值 |
| J91_shared_unary | 共享高分前缀、独立候选发现、单实例局部分割修正 | 其余单因子实验的基础 |
| J92_neighbor | J91加入真实邻实例状态 | J92 vs J91：邻实例条件是否有用 |
| J93_unknown_aware_selection | J91加入证据不足可保持未知的候选关系/集合选择 | J93 vs J91：候选选择贡献 |
| J94_full | 高分证据、邻实例修正、候选选择、有符号增益路由 | J94 vs J99：完整系统下的增益路由贡献 |
| J95_shuffled_neighbor | J92使用打乱的邻实例证据 | J92 vs J95：提升是否来自正确邻域而非额外容量 |
| J96_no_d2 | J91关闭stride-2细节注入，保留其他分支 | J91 vs J96：细节注入贡献；不是删掉整个高分前缀 |
| J97_tiny_balanced | J91的辅助实例损失增加有界小目标权重 | J97 vs J91：仅损失计权的贡献 |
| J98_unary_gain | J91加入有符号增益路由 | J98 vs J91：不混入邻域/选择的路由贡献 |
| J99_full_no_gain | J94关闭增益路由 | J94 vs J99：完整模型的路由消融 |

`screen/priority` 为 J90、J91、J92、J94；`all` 为全部10臂。另有 `neighbors`、`selection`、`detail`、`loss`、`gain`，精确列表见 `citrus_j6_suite.py`。`ONLY` 或 `--only` 可指定逗号分隔的完整模型名，不会自动加入未选模型。

J94的增益监督是在线、同训练样本上相对新实例零logit起点的有限模型 Brier 风险差；训练/推理都在该实例对应scout cell读取。它不是相对global预测的真实收益，不是已经实现的交叉拟合 oracle，也不是提升 AP 或节省高分前缀计算的数学保证。邻实例修正和候选关系同样属于需要消融验证的假设。研究筛选优先比较J90/J91，再决定是否需要J94的扩展，不能预称未训练的J94最强。

## 4. 固定的训练、数据和验证协议

批运行调用 `citrus_j2_batch.settings()`，再明确锁定 J6 必要选项。不要因为旧协议 YAML 中有“预训练”说明或 `mask_ratio: 4`，就认为本系列也使用这些值；有效覆盖如下，并在每个结果目录保存 `j6_protocol.json`。

| 项目 | J6有效值 |
|---|---|
| 初始化 | 从对应 YAML 随机初始化，`pretrained=False`；各臂按同seed初始化，不隐式下载官方权重 |
| 训练轮数/seed | 默认300 / `[42]`；正式主要结论建议相同设置下 `[42,43,44]` |
| 全局图/高分图 | 640 / 1280，坐标严格配准；只有三个检测stride：8、16、32 |
| 训练观测 | 同一原图经过一次1280增强，再用AREA降采样得到640全局图；不先缓存为640图再放大 |
| 验证观测 | 既有640标准验证样本保持不动；从原图另建配准高分图 |
| batch/workers/CPU threads | 默认16 / 4 / 4 |
| cache/AMP | `True` / `False` |
| optimizer | AdamW；不更换新优化器 |
| lr0 / lrf / momentum / weight_decay | 0.001 / 0.01 / 0.937 / 0.0005 |
| warmup | 3轮；warmup_momentum=0.8，warmup_bias_lr=0.1 |
| 基础损失权重 | box=7.5，cls=0.5，dfl=1.5 |
| 辅助损失权重 | scout=0.25，local=0.5，identity=0.1，gain=0.1；未启用的分支不参与对应项 |
| mask_ratio / overlap_mask | 外部2 / True；1280训练内部栅格比4，得到同一320监督尺寸 |
| mosaic / copy_paste | 1.0 / 0.3；close_mosaic=10 |
| rect / multi_scale | 训练False / 0.0；不允许各自额外改分辨率破坏配准 |
| dropout / deterministic / cos_lr | 0.0 / True / False |
| early stopping / time | patience=epochs+1（300轮时301）；time=None，不用时间预算提前截断 |
| 验证 | split=val，conf=0.001，iou=0.7，max_det=300，half=False，save_json=False |
| 绘图 | 默认plots=True；仅显式PLOTS=False或--no-plots时关闭，并写入协议 |
| 验证掩膜栅格 | 全局输入/2；继承EV6匹配/AP，不重写PR补零或改成COCO验证 |

其他增强参数继承 `protocols/citrus_paper1_formal_v2_ram.yaml`；所有有效训练参数另存每个运行的 `args.yaml` 和 `j6_protocol.json`。`--batch`、`--workers` 支持按机器调度，但同一正式对照不得只改其中某一臂的 batch。

所有 J6 臂，包括 J90，均经过同一个双视图数据加载流程。因此 J90是本轮可信的主对照，不应直接把旧系列不同采样/缩放实现的曲线当作同协议因果比较。J90虽不计算辅助高分网络，仍承担配对数据加载开销，必须分别报告纯模型与完整管线性能。

数据沿用户设置的 `DATA`，不会要求输入“确认数据”、扫描图像指纹或改变标签。日志只记录 data.yaml 自身与代码/YAML的SHA，防止在同一输出目录混用不同代码。它不能证明标签正确、划分无泄漏；同路径图像/标签改过之后，请自行换新PROJECT。

`cache=True` 请求RAM缓存，不是保证任何机器均能容纳；框架会检查内存。训练按1280视图缓存，内存需求高于旧640管线。验证高分额外缓存是每个worker最多128MiB的uint8 LRU，不是无限缓存。

## 5. 单个 YAML 的官方 YOLO 接口

本工程的 `YOLO._smart_load()` 会识别 `SegmentCitrusJ6`，自动选择 J6Trainer、J6Validator、J6Predictor；其他模型继续使用原分派。YAML和保存的 `.pt` 都经过同样识别。必须使用当前完整工程，不能换成pip里未修改的官方包。

最简单的单模型训练脚本如下。这个示例也保持随机初始化和相同配方，不是漏传参数的默认训练：

```python
import os

DEVICE = "1"
os.environ["CUDA_VISIBLE_DEVICES"] = DEVICE
os.environ["OMP_NUM_THREADS"] = "4"
os.environ["MKL_NUM_THREADS"] = "4"

from ultralytics import YOLO
from citrus_j6_batch import build_train_args, plotting_preflight
from citrus_j_batch import save_mask_checkpoints

plotting_preflight()  # 默认保留图，开始训练前检查依赖
model = YOLO("0_orange_yaml/J_V6_series/J94_full.yaml", task="segment")
model.add_callback("on_model_save", save_mask_checkpoints)
model.train(
    data="/data/sxq/datasets/orange_yolo/data.yaml",
    device=DEVICE,
    project="/data/sxq/results/J/v6/CITRUS_J6_R2_SINGLE_300EP_01",
    name="J94_full_seed42",
    exist_ok=False,
    **build_train_args(epochs=300, seed=42, workers=4, batch=16),
)
```

也可以显式传入 `trainer=J6Trainer`，两者等价。若使用 `YOLO(yaml).train()` 却落到普通 SegmentationTrainer，说明加载了错误的旧工程，不能继续训练。建议在项目目录执行一次 `python -m pip install -e .` 并检查 `ultralytics.__file__` 指向当前目录；不要因此随意升级旧服务器的torch/CUDA。

单模型验证：

```python
import os
DEVICE = "1"
os.environ["CUDA_VISIBLE_DEVICES"] = DEVICE

from ultralytics import YOLO

model = YOLO("/data/sxq/results/J/v6/CITRUS_J6_ALL_300EP_20261017_R2/J94_full_seed42/weights/best_mask.pt")
metrics = model.val(
    data="/data/sxq/datasets/orange_yolo/data.yaml",
    split="val", device=DEVICE, imgsz=640, batch=16, workers=4,
    cache=True, mask_ratio=2, overlap_mask=True,
    conf=0.001, iou=0.7, max_det=300, half=False,
    save_json=False, augment=False, compile=False,
)
```

测试集将 `split="val"` 改为 `split="test"`，仅在确定最终模型和阈值后使用。不要在测试集上选臂或调阈值。

单模型图片预测：

```python
results = model.predict(
    source="/data/sxq/datasets/orange_yolo/test/images",
    device=DEVICE, imgsz=640, conf=0.25, half=False, save=True, stream=True,
)
for result in results:
    print(result.path, len(result.boxes))
```

预测需要原始图片/视频等可提供原像素的输入，不接受已经缩小的BCHW张量假装高分观测。当前拒绝导出为单输入ONNX/TensorRT、TTA和compile；这不等于这些路径已经实现或验证。显示/保存结果会回到原图坐标，验证指标仍在EV6的输入/2栅格计算。

## 6. 已完成、跑一半、断电与停止

每个模型目录名为 `<模型>_seed<seed>`。全部排队前会检查输出冲突，避免先跑几个才发现后面目录存在。

- 同协议且带有效 `j6_completed.json` 的结果自动跳过，并核查CSV轮数、Mask选优权重和选择记录。
- 部分目录默认报错，不覆盖、不自动续训。若只想跳过它，用 `ONLY` 仅列出其他模型。
- 确需续训时，只对一个seed明确指定模型名；加载对应原目录的 `weights/last.pt`，恢复优化器/调度状态，而不是加载best权重重新训练。
- 正式训练代码、YAML、有效超参或data.yaml改变，不能冒充原运行继续；换新PROJECT。

跳过中断模型，直接跑后面的示例：

```bash
python -u RUN_CITRUS_J6.py --only J92_neighbor,J93_unknown_aware_selection,J94_full
```

显式继续 J94 的300轮目标：

```bash
python -u RUN_CITRUS_J6.py --only J94_full --resume J94_full --seeds 42
```

或者在启动文件设置 `ONLY="J94_full"`、`RESUME="J94_full"`，再点击三角形。此处 `--epochs` 仍是原目标300，不是“再加300轮”。批运行完成后若忘记清空RESUME，已核验完成的原结果仍只跳过，不会重复训练。

这里“续训”指恢复原生checkpoint的epoch、optimizer、scaler和EMA等状态，不承诺逐batch位级复现：原生框架不完整保存Python/NumPy/worker的全部随机状态。中断所在epoch中尚未保存的更新也不会恢复。

请注意 checkpoint 的不同含义：

| 文件 | 作用 | 能否当作精确续训入口 |
|---|---|---|
| 中途的 `last.pt` | 最近一次保存的训练状态 | 有epoch和optimizer时可以；当前进行中的未保存batch会丢失 |
| 正常结束后的 `last.pt` | 框架final_eval会剥离optimizer并设epoch=-1 | 不可以；已经正常完成就应跳过 |
| `best.pt` | 框架原生box+mask fitness选择 | 用于其选择协议，不替代Mask单独选优 |
| `best_mask.pt` | 本系列按Mask AP50–95选择的快照 | 默认用于验证/预测，不当作“最近一步”续训 |
| `best_mask50.pt` | 按Mask AP50选择的快照 | 同上，不能与另一个epoch的Recall拼表 |

已额外增加剥离状态检查：如果部分运行的 `last.pt` 已被final_eval/外部工具剥离，程序明确拒绝，不会静默从头跑。若在最后评估阶段断电，CSV已经达到目标轮数但没有完成标记，也会明确停止让人复核，不把它误判成还需训练。

停止时在当前终端按 `Ctrl+C`。它终止整个队列，不启动下一模型；硬停止/直接断电可能来不及写状态JSON，仍只认可磁盘上最后保存的checkpoint。

## 7. 输出怎么看

每臂保留框架的 `results.csv`、曲线、混淆矩阵、`args.yaml` 和权重。另外保存：

- `j6_protocol.json`：该臂的有效训练设置、初始化与评估协议。
- `j6_sources.json`：相关实现文件SHA与Git状态；包括根目录全部 `citrus_j6*.py`。
- `initialization.json`、`runtime.json`、`train_loaded_files.txt`、`val_loaded_files.txt`：新运行的实际初始化和加载记录；续训不会覆盖最初的初始化记录。
- `j6_run_state.json`：running/interrupted/failed/completed；它是状态说明，不替代完成核验。
- `j6_completed.json`：轮数和Mask选优文件核验成功后才写。
- 项目根目录的 `j6_training_summary.csv`：同一个 `best_mask_selection.json` 指定epoch的 AP50–95、AP50、Precision、Recall；没有选择记录时才退回CSV最大值，并明确标明来源。

AP列是0到1比例，乘100后才是百分数。例如0.78是78%，不是0.78个百分点。不要把不同epoch、不同评估器或不同数据成员的最大指标拼成一行。

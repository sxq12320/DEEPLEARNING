# E V4 现有代码复核与优化（2026-09-09）

## 结论与范围

本次检查范围是 `1_SEVER/code/ultralytics-main-new` 内刚新增的 **26 个 E V4 YAML**、11 个新模块、
它们复用的下采样/上采样/头部实现，以及 SMC、SMCAO、NWD、VFL、边界/query/质量损失和训练入口。
**没有新建模型系列，没有替换这批网络的主体拓扑，没有改数据集和已完成训练结果。**
本文件是代码审计，不是新模型的精度评估，也不代表已经全面审计整个历史仓库或独立的 baseline_choice 工程。

当前最值得先解决的不是再堆模块，而是：正确初始化、有效监督、数值稳定、计算开销。
本次确实发现会干扰实验结论的实现问题，不能把修复前的负结果全部归因于网络思想无效。

## 1. 已修复的问题

| 问题 | 影响 | 本次处理 |
|---|---|---|
| 26 个 YAML 缺少预训练层映射 | 插层后按相同层号匹配，丢失大量 COCO 权重，还可能把同形状的其他层加载进来 | 写入逐层 target→source 映射，新层标为 -1；恢复公共分割预测器；同图/同家族重建不重复映射 |
| DySample 的 xy 网格又 transpose 一次 | 方图坐标错位，矩形验证输入报维度错误 | 修正轴顺序；零偏移应等价 bilinear，上述性质已测试 |
| NWD 在零距离处 sqrt(0) | 精确匹配框也可能产生 NaN 梯度 | 平滑距离 sqrt(d²+1e-8)-1e-4，用 expm1 减少消减误差；混合比例校验 |
| SMC/SMCAO 逃逸计数仅在注入噪声时递增 | 噪声次数用完后，最长持续时间可能永远到不了 | 按优化器更新步数计时，独立限制扰动预算和逃逸时长 |
| 扰动标准差使用整张参数梯度的 L2 范数 | 噪声总强度随参数张量大小增加，所谓相对小扰动可能并不小 | 每个张量的扰动 L2 限定为配置比例 × 梯度 L2 |
| SMC 逐参数 .item()、在 AMP unscale 前观测 | 大量 GPU 同步；监测到的是随 scaler 变化的放大梯度 | 在 unscale 后、clip 前处理；每个设备归约一次梯度范数 |
| 优化器内部 warmup/cosine 与 trainer 重复调度 | 梯度累积下时间轴不一致，还悄悄改变既定线性 LR 协议 | trainer 负责既定 warmup/linear/cosine；控制器只做显式扰动，继承 momentum=0.937 |
| checkpoint 未保存控制器历史 | resume 丢失峰值、计数、逃逸和动态状态 | 保存/恢复完整控制器状态；旧 checkpoint 缺失状态时明确告警 |
| SMCAO 积分无界、负阻尼可在逃逸外作用 | 不受既定时间限制的额外调度 | 积分状态限幅；负阻尼只在限时逃逸期间允许 |
| README 使用错误训练脚本 | train_citrus_seg.py 不接受列出的损失/优化器参数 | 改用现有 train_citrus_yaml.py，增加显式 --optimizer 参数 |
| 拓扑头入口默认自动加 boundary/query | E52“纯头部结构”对照会混入额外损失 | E V4 入口默认两项为 0，E60–E62 必须显式开启 |
| 反向注意力 sigmoid 前使用 SiLU | 学习到的门控无法充分趋近 0 | 去掉该 logit 的 SiLU；仍保留原 BN/卷积参数和残差路径 |

SMC/SMCAO 本质是 **AdamW 外的启发式控制调度**，并不是已经证明更好的新优化器。
本次修复了工程错误，不等于证明它们优于 AdamW。
普通结构消融仍固定 AdamW；E63/E64 是明确标记的优化器对照，不要混入结构增益。

## 2. 计算实现优化与实测边界

- CARAFE：由“高分辨率展开邻域”改成“低分辨率邻域与子像素权重收缩”。
  scale=2 时主要邻域展开张量缩小为原来的 1/4；没有改变重组公式及参数。
- IntegralContext：先在 1×1、2×2、4×4 池化网格做线性通道投影，再上采样求和。
  保持原参数名和数学运算等价，避免在完整特征图上拼接 3C 后卷积。
- ChromaFront：只查询线性 LUT 相邻两个节点，不生成 B×3×P×H×W 的完整基函数。
  batch=16、640、P=8 时，单个旧 FP32 基函数张量约 600 MiB。去除该张量不等于总显存减少恰好 600 MiB。
- LapFront：复用重复的平均池化结果。
- query 标签：按图向量化小实例面积、质心、3×3 邻域生成，避免每个实例把坐标传回 Python。
  不删除小目标标签，不改变原 P2 查询目标规则。
- boundary-only 损失不再额外计算未使用的凹口形态学区域。

本地 CPU、torch 2.8、2 线程、同输入 5 次测量中位数，**仅模块前向+反向**：

| 模块与输入 | 修复前 ms | 修复后 ms | 解读 |
|---|---:|---:|---|
| CARAFE，2×128×40×40 | 555.230 | 142.126 | 此 CPU 微基准约 3.91 倍加速 |
| IntegralContext，2×256×20×20 | 8.898 | 4.728 | 此 CPU 微基准约 1.88 倍加速 |
| ChromaFront，2×3×640×640 | 156.670 | 159.136 | 未观察到 CPU 加速，主要减少大中间张量 |

**不能把上述倍数当作 RTX 3090 整轮训练加速倍数。**当前本机无 CUDA，未做服务器显存/端到端测速。
LUT 在节点处的导数采用分段线性插值的一侧导数；非节点输出/梯度已与原实现对照。
尤其 LUT 的 gather/scatter 在 CUDA 上仍须实测，不应以“33 参数”宣称零成本。

## 4. 对原设计的判断

### 可以保留并实验，但不能预先断言涨点

- E40 的混合主干仍是本系列共同对照，不用因为出现新名字就换掉。
- E42/E43/E44/E46/E70–E74 的残差式注入容易分析；前端新增参数少，但计算量需单独测。
- E57 的原型通道压缩是明确的复杂度对照，需要看严格 Mask AP 和边界指标是否受损。
- E52 与 E60/E61/E62 可用于拆分“头部变化”和“额外监督”。
- E53 附带独立 mask-IoU 质量损失，属于**结构+质量监督**，不是“完全不改训练目标”。
- E41/E45 把 concat 替换成细流输出，输入通道数及可加载权重发生变化。
  局部模块初始化为恒等，不代表整个网络等于 E40，也不代表自顶向下语义一定保留。

### 不应作为论文中已经成立的论断

- 池化上下文不是时间积分，没有因此证明消除了“稳态漏检”。
- 当前前馈残差模块没有建立闭环系统稳定性证明；PID/观测器/串级是设计类比。
- E72 的图没有直接对象监督，不应称为已校准 objectness 或证明“擦除的就是正确果实”。
- E73 只看两方向条带统计，不是完整径向对称算子；遮挡幼果的可见 mask 可以深凹，不能强行圆形填充。
- E74 的 box filtering 不是高斯尺度空间，更不是原版 ZoomNet 复现。
- “切片没用、必须把尺度处理放到特征层”不能由已有部分结果推出。
- PR 末端补零仍是评估实现惯例与最大可达召回共同造成，不能通过改绘图代码证明网络改善。

## 5. 怎样训练这批现有模型

在服务器的 ultralytics-main-new 目录，用已有的 **Python 前台单模型入口**即可：

```bash
python train_citrus_yaml.py --model 0_orange_yaml/E_V4_series/E40_control.yaml --data /data/sxq/datasets/orange_yolo/data.yaml --device 1 --epochs 300 --name E40_control_review1
```

结构模型换 --model 和唯一 --name；其余保持不变。
本次未新建模型或强行启动正式训练，也没有重新打开单 GPU 占用保护。
若继续使用旧批处理器，须确认它实际使用了此批最新 YAML/源代码并显式传递损失参数。
默认继承固定协议：batch=16、imgsz=640、workers=4、cache=True、amp=False、
AdamW、lr0=0.001、lrf=0.01、momentum=0.937、seed=42；完整配置以
protocols/citrus_paper1_formal_v2_ram.yaml 和本次运行的 args.yaml 为准。
不要执行 README 旧版本中的 train_citrus_seg.py 命令，它是另一套旧驱动。

| 已设计实验 | 使用的 YAML | 额外 CLI 参数 |
|---|---|---|
| E58 | E40_control | --nwd-ratio 0.5 |
| E59 | E40_control | --citrus-vfl 0.5 |
| E60 | E52_topo_head | --citrus-boundary 0.25 |
| E61 | E52_topo_head | --citrus-query 0.10 |
| E62 | E52_topo_head | --citrus-boundary 0.25 --citrus-query 0.10 |
| E63 | E41_pid_fusion | --optimizer SMC |
| E64 | E41_pid_fusion | --optimizer SMCAO |

以上 E58–E64 是**原设计中已存在的训练配方编号**，不是漏了七个新 YAML。
先单变量；本次 smoke 中组合开启多项仅为了覆盖接线，不作为任何消融结果。

## 2. 该保留和该收缩的方向

- **保留：真实像素、后续语义识别、同一实例来源、完整多尺度语义链。** 小果仅靠浅层纹理很容易成为叶片/枝条候选；额外像素必须经过同一识别网络，不能只增加候选数就称找回果实。
- **暂不作为默认：独立浅层scout、ROI理想GT训练/预测框部署、邻居选择、多源quality乘分。** 本轮的组合没有净AP收益，机制上仍需同权重干预诊断，不宣布它们原理无效。
- **不误读J96：** 源码仅把ROI采样detail乘零，高分prefix/scout/discovery仍在；J96比J91 AP50–95高0.259点、R低1.582点，既不是“高分无用”的证明，也不是“D2必留”的证明。
- **不误读J97：** tiny权重仅作用局部辅助mask BCE，不改全局TAL/cls/mask。OOM记录不证明权重公式导致OOM；当时23.69GiB卡只剩122MiB可用，无法从此确定其他占用/碎片/瞬时峰值来源。
- **不默认改loss/optimizer：** 此轮没有证据证明训练目标或分配是主要瓶颈。先控制观察和识别路径，否则每次同时变五处又无法判断哪处有效。

## 3. 新增三臂与旧六臂

新增的**J118是本轮优先候选，不是已验证最强模型**。三臂保留标准YOLO11n全部C2/C3/C4/C5、C2PSA、SPPF和完整P3→P4→P5 PAN返回、原生Segment；没有EV11 persistent/fine-Proto或额外身份头。

```text
原始同一张 RGB
├─ G640 → 原生stem/C2/C3 → C3' → 原生C4/C5 → 完整PAN → 同一套box/cls/系数
│                           ↑                                 ↓
└─ H1280 → 16ch窄证据编码 → D80                       原生Proto → 可见实例mask
                            只在C3读入一次
```

15ch只是显式打包同一RGB的两种分辨率：`[G, pixel_unshuffle(H, 2)]`，不是新传感器、不是把dataset改15通道。H按实际G画布配准2倍；缺原像素会报错，不偷用低图代替。只有J117明确使用低图双线性放大。

|配置|作用|Params M|GFLOPs@640|
|---|---|---:|---:|
|J116_native_global_control|完整原生预测路径，当轮共同数据控制|2.842803|10.355763|
|J117_native_c3_upsampled|增加同构接口，但无新原始细节|2.850739|10.709248|
|J118_native_raw_c3|真实高分细节→C3→后续深层识别|2.850739|10.709248|

J118相对J116多7,936参数（约0.28%）、约3.41%计数FLOPs。为完整packed tensor前向、未融合THOP 2FLOPs/MAC；含高分encoder，不含原图resize/缓存/搬运/打包/NMS/系数×Proto合成及部分函数式算子。**不代表GPU延迟或显存只涨3.41%。** 在服务器1–3轮检查后再长训。

旧J110–J115的YAML/结构含义保留，`SUITE="legacy"`可跑；`all`跑9组，但不必全部先跑。J112保留成熟EV11路线，和J118比较是两套整体设计，不能归因成单一“主干修改”的效应。

## 4. 更严格的共同初始状态

同seed不等于同原生初值：C3前构造分支会消耗随机数。新增三臂在fresh训练时，显式按24个语义层从同seed的canonical nc1 YOLO11n scratch参考复制共同参数及BN buffers；逐层核对类型、state键、shape/dtype后再加载。不按插层后的物理编号盲加载，不拿历史best权重预训练。

参考构建隔离CPU Torch RNG，不触发CUDA，不改分支、Python/NumPy状态或optimizer。保存 `j7r_native_initialization.json` 与共同state SHA256。J117/J118同seed全state一致，gain=0起点下三臂global前向一致；后续gain能学习。续训/提供权重不重初始化，输入相同但架构不同的checkpoint拒绝重解释。

这不是J90旧训练的逐位复现；J116必须真的训练，不能把63.636直接填给它。RAM cache和多worker仍可能影响随机流，首批摘要也不证明整段训练bitexact。

## 5. 超参与验证不变

scratch、AMP=False、cache=True、AdamW lr0=.001/lrf=.01/WD=.0005，batch16、imgsz640、mask_ratio2、CP=.3、mosaic1/close10、seed42、300轮；其它固定设置仍见前版完整表及 `j7r_protocol.json`。没有自定义新loss或优化器。

**原生Proto输出/4，但监督与验证GT仍为实际input/2。** 当前项目的 `v8SegmentationLoss` 在尺寸不同时将Proto logits插值到GT画布计算mask loss，而非把GT缩到/4；EV6同样在阈值前插值。原rect padding保留，名义640可能实际672，GT336；不硬编码320。

终评仍按`best_mask.pt`，在`selected_mask_validation/`一起保存选权重记录、指标、PR匹配审计。发现J96旧根PR图legend .783不等所选mask轮AP50 .77913：J6继承的终评用best.pt，不是本表选中的best_mask.pt，不能混用图和表。原始结果未改。

PR横轴为Recall；本地 `compute_ap` 在最大实测recall后追加零精度哨兵，末端归零不意味着confidence到0.85崩溃。新模型不改曲线算法，保存真实Rmax、R@P90/P95及raw score/TP/FP；不能承诺曲线到Recall=1仍高P。混淆矩阵中的框TP/FN/FP也不能直接证明叶片颜色混淆，需要逐实例难例分析。

## 6. 依据与能证伪的问题

[ESOD](https://arxiv.org/html/2407.16424v2)启发将高分观察和后续识别职责分开；我们不采用其稀疏切片实现，也不据论文结论保证本任务收益。[OSFormer](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136780019.pdf)区分实例语义与高分mask特征，不是“所有浅层特征都拿来独立检测”。本次承接既有文献复读与自身J6失败证据，未冒称新读数百篇或原创普通残差公式。

额外观察H经降采样得到G是多对一过程，存在不同H映射到同一G；仅使用G的确定网络无法区分这些H。这只说明额外像素可能有信息价值，不证明其对果实标签有增量信息，更不证明有限训练会用好它。相位重排可逆，后续16ch投影有损，不宣称无损抗混叠。

实际判定：J118 vs J117检验相同图、共同初始化下额外真实观察；J118 vs J116检验整个方案是否净胜。若raw不胜pseudo，不继续靠堆分支解释；若两者均不胜global，先回到逐GT漏检/低分/框覆盖/mask质量归因。只有单seed涨点仍不能证明稳健，最终方法/基线需正式固定划分3seed。test不选结构。

result-to-claim审查为`no`，针对旧J6联合提升主张；同家族/provisional。它支持做这个可否证工程转向，不是新模型性能认证或论文创新认定。

## 7. 如何运行

上传完整更新后的`code/ultralytics-main-new`，不要只复制三个YAML。沿用已能训练的Python/Torch环境，不需要Mamba/DCN等新编译依赖。编辑`RUN_CITRUS_J7R.py`：

```python
DATA = "/你真实的数据集/data.yaml"
DEVICE = "1"  # 物理GPU1；绑定后显示logical0正常
SUITE = "priority"  # J116 → J117 → J118
EPOCHS = 300
PROJECT = "/data/sxq/results/J/v7r/CITRUS_J7R_NATIVE_300EP_20261019"
```

先用另一个新PROJECT跑1–3轮（PLOTS=True）确认服务器图表/显存，再用正式新PROJECT跑300轮；确认后仍可VSCode右上角三角形前台顺序跑：

```bash
python RUN_CITRUS_J7R.py --dry-run
python RUN_CITRUS_J7R.py
```

默认3组；ONLY="J118"单跑，SUITE="legacy"旧6组，SUITE="all"9组。无nohup、无数据确认门禁、无单卡占用保护；Ctrl+C停全队列，失败不启动下一组。OOM保留原错误及本进程显存诊断，不自动改AMP/batch。半成品不覆盖；更换共同batch要给所有对照统一设置、换新PROJECT。

纯YOLO API仍支持native YAML自动选择配对adapter；任意RGB-only tensor直接给模型会被拒绝，原图路径predict有预处理。导出/TTA/compile未认证，公开入口明确拒绝，不能声称已具备部署导出支持。

# 柑橘实例分割下一代架构：先找全，再辨真，最后细化

日期：2026-09-23。状态：**研究设计，未实现、未训练，不承诺涨点**。现有 I_V3 十组仍是灰度/局部对比支路的受控实验，不把它们称作最终模型，也不改动已准备运行的脚本。

## 一、证据先于结构

| 观察 | 证据与限制 | 对架构的约束 |
|---|---|---|
| 原图极小果实候选不足 | 旧验证集 I20，`<16×16` 的 161 个目标在 conf=0.25 时仅匹配 25 个；细切片匹配约 84 个 | 需要在**像素还存在的尺度**搜索；单纯加强 mask 解码不能恢复没有被提议的实例 |

## 三、候选主架构：轻量“搜索—辨真—细化”网络

设计目标是一次共享特征抽取后解决两个不同错误：**漏掉极小果实**与**把叶片/背景当成果实**。这不是在 YOLO11n 上堆几个注意力模块，而是改变候选分配和实例判别的计算路径。框图：

```text
RGB 640×640
   ├─ 共享轻量主干 ── P3/P4/P5 语义 ──────────── 常规尺度候选
   │         └─────── 宽度受限的 P2/stride-4 细节 ── 1 通道极小目标搜索图
   │                                                └─ top-K 候选中心/局部特征
   └─────────────────────────────── 实例共享 mask prototype
                                                      ↓
                 常规候选 + P2 小目标候选 ── 去重/匹配
                                                      ↓
                     候选级“内部 vs 邻域”证据判别
                        ├─ 果实内部纹理/边界证据
                        ├─ 周边叶片/枝条背景证据
                        └─ P3/P4 软语义支持，不作硬否决
                                                      ↓
                      质量分数 + box + mask 系数
                                                      ↓
                         只对保留实例做 mask 细化
```

### 3.1 搜索：低成本且不被粗尺度一票否决

- 主干仍是**一个共享 RGB 编码器**；保留窄 P2 细节流。灰度/局部对比支路只在 I_V3 正式数据实验明确有利时并入主线，否则删除。灰度是 RGB 的确定性变换，不能伪装成独立模态。
- P2 不接整套高通道 box/cls/mask 密集塔，而输出低通道中心热图 + 少量局部描述子；P3–P5 保留常规果实候选。这直接针对“I22/I23 密集 P2 不稳定且计算增大”的观察。
- P3 语义只能作为**软加分/减分**，不能乘到零；否则 P3 已漏掉的极小目标无法被 P2 挽回。候选上限 `K`、最小中心间距和分数阈值需要在正式验证集定标。
- 训练中心以**可见 mask 内部点**为目标（例如 mask 距离变换最大点），不盲用凹形遮挡果实的 bbox 中心；但过小/空 mask 必须有确定性的退化规则。这个选择是待验证的实现假设，不是文献既有结果。

### 3.2 辨真：让果实与其周围背景作对照

- 对候选 `i`，从 P2 取得中心特征 `f_i` 与局部邻域特征 `r_i`，并从 P3/P4 取得低成本语义 `s_i`。训练一个小型共享分类器处理 `[f_i, r_i, f_i-r_i, s_i]`，输出“真果实证据”及 mask 质量估计。候选数量受 `K` 限制，避免整张 P2 上运行局部注意力。
- 邻域不是圆形先验，也不要求果实 mask 凸/连通。条带状叶枝遮挡会造成深凹可见 mask；只能让网络学习**相对证据**，不得硬性施加圆度/凸包/单连通约束。
- 正例来自标注果实，负例从未匹配、得分高的候选中抽取；没有叶片标签时只能称“困难背景负例”，不能声称有显式“叶片监督”。先人工审阅一批负例，避免标注遗漏把真果实当负例。
- 保留原始候选分数和新证据分数，使用可关闭的有界残差校正。若验证模块让小目标召回下降，则此判别器必须可回退，不把“去误检”误当总体提升。

### 3.3 细化：把昂贵计算只花在保留的实例上

- 第一版沿用共享高分辨率 prototype 与实例 mask 系数，不添加全图第二个重型解码器；只对分数/质量不确定的少量小目标尝试局部 mask 修正。
- 细化路径须分别测“无细化”“只细化极小目标”“细化全部候选”；首轮不默认启用，以免把主干、候选与 mask 收益混在一起。
- 对分离接触果实，评估 split/merge、实例间隙与边界 F1；对叶片遮挡，评估可见 mask 的凹陷与保留面积，不能用简单圆形补全掩膜。

### 3.4 原始高分辨率补救：单列系统方案，不伪装成网络增益

640 缩放后已经消失的像素，P2 也无法凭空恢复。完整方案可增加**独立的、固定预算的原始分辨率复查**：全图模式先运行，然后由高召回、低成本的原图搜索信号选择少量 ROI 复查；该信号必须在正式验证集量化 tiny 候选覆盖率。任何完全依赖低分辨率粗候选的选择器都可能漏掉那些最困难目标；只有扫描所有切片才有确定的空间覆盖，所以“选择性 ROI 有保证召回”是错误表述。若候选覆盖不够，则回到固定网格切片作为速度更慢的参考，而不是宣称自适应切片有效。

网络本身的参数/GFLOPs和“全图+复查”的端到端延迟、误检分别报告，不能以单次网络 FLOPs 掩盖切片成本。

## 四、损失、优化与验证顺序

1. **先保持现有 AdamW、AMP=False、640、输入/增广和训练轮数不变**，只验证搜索路径。热图可用 focal/BCE 类监督，但权重单独扫描；小目标 `<8`、`8–16`、`16–32` px 的 Recall 与候选上界要先于最终 AP 检查。
2. 搜索确实提高召回后，才加入候选级困难背景判别。先用现有 box/mask/class 损失，不同时改 NWD、Dice、动态权重；需要时再做各自单因素消融。
3. 最后测试质量分数重排与局部 mask 细化。分数校准在验证集完成，独立 test 只运行一次；同时报告 AP50、AP50-95、R@P≥0.90、最大召回、PR 原始点与 FP/图。
4. 用同协议 RGB 锚点、I_V3 最佳支路、`+P2 搜索`、`+背景判别`、`+mask 细化` 的递进对照。第一轮只跑 50 epoch/单 seed 筛选；有效者才做相同 300 epoch、三个 seed、按拍摄组 bootstrap 置信区间。
5. 记录 Params/GFLOPs **以及同一 GPU/批大小的训练秒/epoch、单图全流程延迟、显存**。目标先设为相对锚点的 Pareto 改进，而不是未经验证承诺“+10 点”。

关键停止条件：若 P2 搜索使 tiny 候选召回不升或错误候选激增；若候选验证以牺牲 R@P≥0.90 换取表面 precision；若完整延迟超出用户可接受范围，则中止该路线，不继续堆模块。

## 五、TypeSafe 结构化辅助审查

已将不含原始图像、标注、权重、代码和个人路径的摘要提交到用户指定 API；响应见 `E:/mastercode/_work/20260923_i_v3_review/typesafe_architecture_response.json`。它在四个候选方向中对“选择性高分辨率 ROI”给出概率 0.42、选择置信度仅 0.23；对完整稠密双主干的高风险判断为 0.93，并将“粗尺度候选可能漏掉极小目标”的风险评为 1.97/2。**这不是性能预测或学术审稿**：低置信排序不能压过实测证据。因此架构主线先做低成本 P2 搜索与候选判别，ROI 复查只作为后置系统实验。

## 六、最终立场

“完美网络”无法从论文拼接推出。当前最有依据的路线是：**共享主干保轻量、高分辨率低成本搜索补漏、候选级前景/背景判别去伪、按需 mask 细化、原图复查与网络指标分账**。真正的论文贡献必须由正式无泄漏划分、同协议基线、消融、三 seed 和全流程速度共同证明；只凭旧结果或 TypeSafe 评分都不能宣称已获得最强模型。

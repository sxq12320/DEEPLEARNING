## 2. 新架构不是继续往 YOLO 主干上堆模块

J02–J19 的 backbone 是 **JStem → JDown/JStage 非 CSP 分层特征提取 → 深层固定记忆上下文**，没有 C3k2。保留通用 SPPF 与标准 P3/P4/P5 box/class/mask-coefficient 接口，借用 Ultralytics 训练、分配及 NMS 框架，不称为彻底脱离 YOLO。

总体路线：

1. RGB 原路保留，可选显式亮度/局部对比；相位重排之后再做通道压缩。
2. stride4 细节早期保留；stride8/16/32 提取语义，深层仅用 16 个 pooled memory 位置做上下文读出。
3. 每个输出尺度直接选择并融合不同主干来源，一次完成，不串行完整 FPN→PAN 往返。不是所有尺度两两交叉注意力。
4. 分类可接收零初始化、有界的软前景调制；框与系数直接路径不被该门控更改。没有硬删除前景之外候选。
5. 掩膜单独在原生 stride4/2 细节上解码；可选按 GT 实例归一化的 tiny Dice 与可见边界监督。

J11 是**综合候选**，不是当前已知最强模型。J17 是更窄预算版本。主干、融合、头部、损失和训练机制均有明确对照，而非给 20 个相近网络随意改名。

## 4. PR 问题：诊断真实漏检，而非把图画平

PR 图横轴是 Recall，**不是置信度**。当真实最大召回是 R_max<1 时，评估函数会在计算/绘制插值包络时扩展末尾零精度；这不表示某个“85%置信度”预测精度全部归零。

真实问题是：低阈值下仍未覆盖哪些 GT？新增低分候选是果实还是叶枝？掩膜 IoU、候选定位、重复抑制哪一环失效？必须看原始匹配数组、固定阈值 TP/FP/FN、tiny 与低对比子集，而不是要求 Recall=1 的尾端保持高精度。

2026-10-02 按用户要求，J 恢复 I 系列的 `EV6Validator`，每轮验证原图、input/2 GT 与预测 logit 栅格，输出框/掩膜 P、R、mAP50、mAP50-95 及原有 PR、混淆矩阵。**不接入 baseline 的 COCO 验证器，也不修改原有 PR 曲线绘图算法。** `DIAGNOSE_PR=False` 是默认值，避免训练后再进行额外验证；如主动开启，`observed_pr.json` / CSV 仅保留同一原生验证协议下的实际匹配点，不替代原有曲线或最佳权重选择。

尚未证明：大幅涨点、优于 G10 的同协议结果、真实速度改善、有效减轻果叶混淆、拓扑 split/merge 改善、最终论文贡献充分性。低参数新主干也可能识别能力不足；50轮 scratch 对照可能未充分收敛，不能凭一次小幅差异过早下结论。

## 8. 论文应验证的三个候选贡献，不提前包装为已证实创新

1. **预算受控的细节—语义异构编码与原生细节解码**：检验小目标支持和轻量表示的联合权衡，而不是声称像素绝对无损。
2. **竞争尺度融合与固定预算差分上下文辨别**：检验同色复杂背景下的相对证据，避免稠密全局 attention；零和抵消的条件性证明见数学文档。
3. **软场景组织与可见实例监督的任务分路**：检验未匹配小目标、深凹遮挡与近接实例三个子问题，不做圆形补全或硬前景裁掉。

这些组件思想已有相关工作；是否具有组合之外的研究新意，要由更完整的 related work、对照和子集证据判定。数学推导见 `J_SERIES_MATH_20261001.md`；参考取舍见 `J_SERIES_LITERATURE_20261001.md`。最终目标是选出真实精度/速度 Pareto 最好的模型，不是保证 J11 必须获胜。
